# 0.2.0 — The connector fleet goes wide: 15+ new sources, multi-instance connectors, and a built-in OAuth2 provider

**Released:** February 11, 2026 · **Channel:** Stable · **Tag:** [`v0.2.0`](https://github.com/pipeshub-ai/pipeshub-ai/releases/tag/v0.2.0)

0.2.0 is a very large release — 260+ merged PRs — centered on turning PipesHub's connector layer into a real platform. More than fifteen new data sources land (Jira, Box, S3, MinIO, Google Cloud Storage, Azure Blob, Azure Files, Nextcloud, Notion, Linear, Zammad, Zoom, Google Drive, Monday, Snowflake, Salesforce), connectors gain multi-instance support with per-instance filters, and knowledge bases are re-architected as first-class connectors with their own migration. Under the hood, a new database abstraction layer makes ArangoDB access fully async and removes the direct Arango dependency from the Node.js API.

Operators also get meaningful security hardening (logout token invalidation, captcha, password-reset fixes, the MongoDB "Mongobleed" CVE fix), a PipesHub OAuth2.0 authorization server with JIT account provisioning, and new deployment options: a Helm chart, Kafka SASL, Redis TLS, and S3-compatible object storage for internal blobs.

## Breaking changes & upgrade notes

- Knowledge bases are migrated into connector form on upgrade ([#1371](https://github.com/pipeshub-ai/pipeshub-ai/pull/1371)); related KB/folder migrations run automatically ([#1170](https://github.com/pipeshub-ai/pipeshub-ai/pull/1170), [#1179](https://github.com/pipeshub-ai/pipeshub-ai/pull/1179), [#1406](https://github.com/pipeshub-ai/pipeshub-ai/pull/1406), [#1452](https://github.com/pipeshub-ai/pipeshub-ai/pull/1452)).
- The deprecated "Public connector URL" setting was removed from frontend and backend ([#1233](https://github.com/pipeshub-ai/pipeshub-ai/pull/1233), [#1337](https://github.com/pipeshub-ai/pipeshub-ai/pull/1337)).
- Individual account creation was removed ([#1382](https://github.com/pipeshub-ai/pipeshub-ai/pull/1382)); `common` is no longer the default Microsoft tenant ID ([#1267](https://github.com/pipeshub-ai/pipeshub-ai/pull/1267)).
- New environment variables control rate limiting and access/refresh-token lifetimes ([#1255](https://github.com/pipeshub-ai/pipeshub-ai/pull/1255)); LLM row-processing count for tables is now env-configurable ([#1319](https://github.com/pipeshub-ai/pipeshub-ai/pull/1319)); Kafka partitions default to 1 ([#1384](https://github.com/pipeshub-ai/pipeshub-ai/pull/1384)).

## Highlights

### 15+ new connectors and datasources

The connector catalog roughly triples this release: Jira ([#1098](https://github.com/pipeshub-ai/pipeshub-ai/pull/1098) — @darshangodase), Box ([#1136](https://github.com/pipeshub-ai/pipeshub-ai/pull/1136) — @SharmaNishchay), S3 ([#1235](https://github.com/pipeshub-ai/pipeshub-ai/pull/1235) — @Kushagra1122), MinIO via S3-compatible API ([#1249](https://github.com/pipeshub-ai/pipeshub-ai/pull/1249) — @abhishekgml1991), Google Cloud Storage ([#1315](https://github.com/pipeshub-ai/pipeshub-ai/pull/1315)), Azure Blob Storage ([#1316](https://github.com/pipeshub-ai/pipeshub-ai/pull/1316)), Azure Files ([#1433](https://github.com/pipeshub-ai/pipeshub-ai/pull/1433) — @Kushagra1122), Nextcloud ([#1310](https://github.com/pipeshub-ai/pipeshub-ai/pull/1310) — @SharmaNishchay), Notion ([#1302](https://github.com/pipeshub-ai/pipeshub-ai/pull/1302) — @shrikantNemiwal1), Linear ([#1198](https://github.com/pipeshub-ai/pipeshub-ai/pull/1198) — @darshangodase), Zammad ([#1346](https://github.com/pipeshub-ai/pipeshub-ai/pull/1346) — @darshangodase), Zoom ([#1002](https://github.com/pipeshub-ai/pipeshub-ai/pull/1002) — @roy-sid), and dedicated Google Drive personal and enterprise connectors ([#1258](https://github.com/pipeshub-ai/pipeshub-ai/pull/1258) — @R0gue-one). New datasource clients also arrive for Monday ([#1299](https://github.com/pipeshub-ai/pipeshub-ai/pull/1299)), Snowflake ([#1303](https://github.com/pipeshub-ai/pipeshub-ai/pull/1303), [#1304](https://github.com/pipeshub-ai/pipeshub-ai/pull/1304) — @rish664), and Salesforce ([#1289](https://github.com/pipeshub-ai/pipeshub-ai/pull/1289) — @jatingaur18).

### Multi-instance connectors with filters and lifecycle management

You can now run multiple configured instances of the same connector ([#1151](https://github.com/pipeshub-ai/pipeshub-ai/pull/1151) — @vishwjeet-pawar03), each with its own credentials and sync filters. The surrounding lifecycle matured across the release: connector filters with dynamic filter-option APIs ([#1202](https://github.com/pipeshub-ai/pipeshub-ai/pull/1202), [#1169](https://github.com/pipeshub-ai/pipeshub-ai/pull/1169) — @shrikantNemiwal1), separate API routes for saving auth and filters ([#1192](https://github.com/pipeshub-ai/pipeshub-ai/pull/1192)), instance rename ([#1166](https://github.com/pipeshub-ai/pipeshub-ai/pull/1166)), instance deletion ([#1350](https://github.com/pipeshub-ai/pipeshub-ai/pull/1350)), a connector-status check before indexing ([#1191](https://github.com/pipeshub-ai/pipeshub-ai/pull/1191)), and a corrected default admin scope of "team" ([#1168](https://github.com/pipeshub-ai/pipeshub-ai/pull/1168)).

### Knowledge bases become connectors, plus a Knowledge Hub API

Knowledge bases were re-architected as a connector type with an automated migration ([#1371](https://github.com/pipeshub-ai/pipeshub-ai/pull/1371) — @tushar1245, follow-ups [#1403](https://github.com/pipeshub-ai/pipeshub-ai/pull/1403), [#1406](https://github.com/pipeshub-ai/pipeshub-ai/pull/1406)) and renamed to "Collections" in the UI ([#1386](https://github.com/pipeshub-ai/pipeshub-ai/pull/1386) — @vishwjeet-pawar03). A new Knowledge Hub API unifies browsing and search over all knowledge ([#1232](https://github.com/pipeshub-ai/pipeshub-ai/pull/1232), [#1334](https://github.com/pipeshub-ai/pipeshub-ai/pull/1334) — @shrikantNemiwal1), backed by KB and folder migrations ([#1170](https://github.com/pipeshub-ai/pipeshub-ai/pull/1170), [#1179](https://github.com/pipeshub-ai/pipeshub-ai/pull/1179)) and an all-records page in the frontend ([#1374](https://github.com/pipeshub-ai/pipeshub-ai/pull/1374)).

### Graph database abstraction layer, async ArangoDB

A new database abstraction layer introduces an `IGraphDBProvider` interface, an aiohttp-based HTTP client for fully async ArangoDB operations, and a `GraphDataStore` with transaction management via context managers; connectors were migrated off the old `BaseArangoService` ([#1145](https://github.com/pipeshub-ai/pipeshub-ai/pull/1145) — @tushar1245, follow-up fixes [#1194](https://github.com/pipeshub-ai/pipeshub-ai/pull/1194), [#1195](https://github.com/pipeshub-ai/pipeshub-ai/pull/1195), [#1197](https://github.com/pipeshub-ai/pipeshub-ai/pull/1197)). The `syncPoint` collection was flattened ([#1181](https://github.com/pipeshub-ai/pipeshub-ai/pull/1181)) and the Node.js API dropped its direct ArangoDB dependency entirely ([#1455](https://github.com/pipeshub-ai/pipeshub-ai/pull/1455) — @vishwjeet-pawar03).

### PipesHub as an OAuth2.0 provider, JIT provisioning, and security hardening

PipesHub now ships its own OAuth2.0 support ([#1321](https://github.com/pipeshub-ai/pipeshub-ai/pull/1321) — @rish664) with the spec published in OpenAPI ([#1324](https://github.com/pipeshub-ai/pipeshub-ai/pull/1324)), JIT account provisioning ([#1347](https://github.com/pipeshub-ai/pipeshub-ai/pull/1347) — @abhishekgml1991) and generic OAuth JIT support ([#1453](https://github.com/pipeshub-ai/pipeshub-ai/pull/1453)). Hardening includes token invalidation on logout ([#1162](https://github.com/pipeshub-ai/pipeshub-ai/pull/1162) — @tushar1245), captcha verification on auth flows ([#1241](https://github.com/pipeshub-ai/pipeshub-ai/pull/1241), [#1294](https://github.com/pipeshub-ai/pipeshub-ai/pull/1294)), password change/reset fixes ([#1257](https://github.com/pipeshub-ai/pipeshub-ai/pull/1257)), a user-enumeration fix ([#1273](https://github.com/pipeshub-ai/pipeshub-ai/pull/1273)), and the MongoDB "Mongobleed" CVE-2025-14847 fix ([#1252](https://github.com/pipeshub-ai/pipeshub-ai/pull/1252) — @loganaden).

### Citations that are actually usable

Citation handling in answers was overhauled: filenames now appear in citations ([#1187](https://github.com/pipeshub-ai/pipeshub-ai/pull/1187) — @vishwjeet-pawar03), citations for the same file are grouped ([#1200](https://github.com/pipeshub-ai/pipeshub-ai/pull/1200)), and numbering was fixed across streaming, non-sequential, and overflow cases ([#1172](https://github.com/pipeshub-ai/pipeshub-ai/pull/1172), [#1188](https://github.com/pipeshub-ai/pipeshub-ai/pull/1188), [#1205](https://github.com/pipeshub-ai/pipeshub-ai/pull/1205), [#1206](https://github.com/pipeshub-ai/pipeshub-ai/pull/1206)). Citation metadata gained a `previewRenderable` flag so the UI knows what it can preview ([#1226](https://github.com/pipeshub-ai/pipeshub-ai/pull/1226)), and source links were fixed ([#1300](https://github.com/pipeshub-ai/pipeshub-ai/pull/1300)).

### Smarter document parsing: VLM OCR, structured output, spreadsheets

A VLM-based OCR strategy joins the parsing pipeline ([#1148](https://github.com/pipeshub-ai/pipeshub-ai/pull/1148) — @kaushal1999) alongside structured output for specific LLMs in indexing and query ([#1144](https://github.com/pipeshub-ai/pipeshub-ai/pull/1144), fix [#1178](https://github.com/pipeshub-ai/pipeshub-ai/pull/1178)). Spreadsheet handling matured significantly: multi-row header handling with LLM header detection in the Excel parser ([#1368](https://github.com/pipeshub-ai/pipeshub-ai/pull/1368)), refactored CSV processing ([#1456](https://github.com/pipeshub-ai/pipeshub-ai/pull/1456), [#1336](https://github.com/pipeshub-ai/pipeshub-ai/pull/1336), [#1344](https://github.com/pipeshub-ai/pipeshub-ai/pull/1344)), TSV support including in-chat rendering ([#1339](https://github.com/pipeshub-ai/pipeshub-ai/pull/1339), [#1354](https://github.com/pipeshub-ai/pipeshub-ai/pull/1354)), and SVG image indexing ([#1199](https://github.com/pipeshub-ai/pipeshub-ai/pull/1199)).
