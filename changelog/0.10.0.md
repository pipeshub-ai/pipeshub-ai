# 0.10.0 — Deleted records go to the trash, agents search the knowledge graph, and a broad security sweep

**Released:** October 12, 2026 · **Channel:** Stable · **Tag:** [`v0.10.0`](https://github.com/pipeshub-ai/pipeshub-ai/releases/tag/v0.10.0)

0.10.0 is a large release: 373 merged PRs since [0.9.1](0.9.1.md). Deleted records can now go to the trash and be restored, behind a Labs setting that is off by default. Agents get knowledge-graph entity tools backed by a new entity index. AI models can be discovered from a provider and added several at a time, and the agent loop uses provider prompt caching. Connectors now remove what was deleted at the source, or left out by a narrowed filter, in [nine connector families](#connectors-remove-what-the-source-deleted). On Redis Streams, each connector is given the least-loaded indexing lane and keeps it, instead of hashing onto one.

A lot of this release is security work. The coding sandbox now has its network off by default, and it reaches Docker only through a policy proxy, with the app running as a non-root user. Custom STDIO MCP servers are opt-in for the operator. Three GitHub security advisories are fixed, along with org scoping, SSRF, CORS and secret-masking issues across the services. **Several of these changes need an operator to act. Read [Breaking changes & upgrade notes](#breaking-changes--upgrade-notes) before upgrading.**

## Breaking changes & upgrade notes

- **Coding sandbox:** `SANDBOX_MODE` (Helm `config.sandboxMode`) must be set. If it is unset or has an unknown value, the sandbox is now unavailable instead of falling back to `local` ([#3725](https://github.com/pipeshub-ai/pipeshub-ai/pull/3725)). `local` also needs `SANDBOX_ALLOW_LOCAL=true` (Helm `config.sandboxAllowLocal: true`) ([#3803](https://github.com/pipeshub-ai/pipeshub-ai/pull/3803)). `SANDBOX_ALLOW_NETWORK` (Helm `config.sandboxAllowNetwork`) now defaults to `false` ([#3780](https://github.com/pipeshub-ai/pipeshub-ai/pull/3780)). Docker Compose installs gain a `docker-socket-proxy` service under the `sandbox` profile. The app reaches it through `DOCKER_HOST=tcp://docker-socket-proxy:2375` and runs as uid 1000, so custom volume mounts must be writable by that user ([#3782](https://github.com/pipeshub-ai/pipeshub-ai/pull/3782)). Helm DinD sandboxes go through the proxy too ([#3888](https://github.com/pipeshub-ai/pipeshub-ai/pull/3888)).
- **MCP:** existing custom STDIO MCP servers stop running until the operator sets `MCP_ALLOW_CUSTOM_STDIO=true` in the Compose `.env`, or `config.mcpAllowCustomStdio: true` in Helm values. STDIO env names on the denylist (`PATH`, `LD_*` and others) are refused ([#3887](https://github.com/pipeshub-ai/pipeshub-ai/pull/3887)).
- **Service-to-service auth:** the parsing and extraction services require a service token ([#3818](https://github.com/pipeshub-ai/pipeshub-ai/pull/3818)). The query and connector services no longer send wildcard credentialed CORS ([#3890](https://github.com/pipeshub-ai/pipeshub-ai/pull/3890)).
- **Redis Streams lanes:** `FAIR_SCHEDULING_LANE_ASSIGNMENT` (Helm `messageBroker.laneAssignment`) defaults to `assigned`. Set it to `hash` on every service to go back to hashed lanes. Events already on a stream are not moved: a connector gets its lane on its first publish after the upgrade, and anything already queued finishes on its old lane. Kafka is not affected ([#3982](https://github.com/pipeshub-ai/pipeshub-ai/pull/3982)).
- **Invites:** `POST /users/bulk/invite` now returns `{ "queued": true }` once the emails are accepted for delivery. A `200` no longer means they were delivered ([#2906](https://github.com/pipeshub-ai/pipeshub-ai/pull/2906)).
- **API status codes and shapes:**
  - A member who calls an admin-only route gets `403`, not `400` ([#3696](https://github.com/pipeshub-ai/pipeshub-ai/pull/3696), [#3827](https://github.com/pipeshub-ai/pipeshub-ai/pull/3827)).
  - Stats on a connector the caller can't open return `404`, not `403` ([#3922](https://github.com/pipeshub-ai/pipeshub-ai/pull/3922)).
  - A sync toggle or resync for such a connector returns `404`, not `500` ([#3955](https://github.com/pipeshub-ai/pipeshub-ai/pull/3955)).
  - A resync that can't be queued returns `503` ([#3910](https://github.com/pipeshub-ai/pipeshub-ai/pull/3910)).
  - Malformed storage ids return `400`, not `500` ([#3668](https://github.com/pipeshub-ai/pipeshub-ai/pull/3668)).
  - The restore refusal field `record_id` is now `blockedRecordId` ([#3986](https://github.com/pipeshub-ai/pipeshub-ai/pull/3986)).
  - Two knowledge-base record-creation routes on the connectors service, which could only answer `500`, are removed ([#3933](https://github.com/pipeshub-ai/pipeshub-ai/pull/3933)).
- **Downloads and secrets:**
  - The connectors service's signed download URLs are bound to the user who redeems them, and still expire after 60 minutes ([#3723](https://github.com/pipeshub-ai/pipeshub-ai/pull/3723)).
  - On the storage service's internal download route, `expirationTimeInSeconds` is capped at 7 days. The default is still 1 hour, and a longer value is refused with `400` ([#3790](https://github.com/pipeshub-ai/pipeshub-ai/pull/3790)).
  - Connector config responses mask stored secrets and no longer return the owner's tokens ([#3917](https://github.com/pipeshub-ai/pipeshub-ai/pull/3917), [#3923](https://github.com/pipeshub-ai/pipeshub-ai/pull/3923)). Admins can read secrets back through a dedicated route ([#3948](https://github.com/pipeshub-ai/pipeshub-ai/pull/3948)).
  - Toolset credentials are hidden from members and masked for admins ([#3775](https://github.com/pipeshub-ai/pipeshub-ai/pull/3775)).
- **Python dependencies:** FastAPI moves to 0.136.3, and Starlette is pinned to 1.7.0 ([#3817](https://github.com/pipeshub-ai/pipeshub-ai/pull/3817)). This changes what callers of the Python service ports see directly. The gateway, UI, Slack and MCP already send the right headers, so they are not affected.
  - JSON requests without `Content-Type: application/json` get `422` instead of being parsed.
  - URL-encoded forms are limited to 1000 fields and 1 MiB per field, and a form over either limit gets `400`. Multipart uploads are not limited.
  - CORS responses echo the request `Origin` and always send `Vary: Origin`.

## Highlights

### Deleted records go to the trash, and can be restored

With the Labs setting `ENABLE_SOFT_DELETE` on, a delete marks a record instead of removing it. This covers user deletes, KB folder deletes and connector sync deletes. The record keeps its edges, permissions and stored content, and it disappears from search and listings ([#3695](https://github.com/pipeshub-ai/pipeshub-ai/pull/3695), [#3718](https://github.com/pipeshub-ai/pipeshub-ai/pull/3718)). A deleted batch can be restored exactly as it was ([#3799](https://github.com/pipeshub-ai/pipeshub-ai/pull/3799)). Collections get a **Recently deleted** page ([#3884](https://github.com/pipeshub-ai/pipeshub-ai/pull/3884)). An hourly job in the connectors service, run by one replica at a time, purges records once they have been in the trash for the retention period: 14 to 28 days by default, set by `softDeletePurge` in the platform settings ([#3847](https://github.com/pipeshub-ai/pipeshub-ai/pull/3847)). Trashed folders refuse moves, creates and uploads ([#3973](https://github.com/pipeshub-ai/pipeshub-ai/pull/3973)). Tables in the trash no longer show up in the full-record tool's foreign-key lists ([#3903](https://github.com/pipeshub-ai/pipeshub-ai/pull/3903)). A vectors-cleanup event the broker refuses counts as unpublished ([#3901](https://github.com/pipeshub-ai/pipeshub-ai/pull/3901)). Records stored before the `isDeleted` field existed count as live ([#3800](https://github.com/pipeshub-ai/pipeshub-ai/pull/3800), [#3825](https://github.com/pipeshub-ai/pipeshub-ai/pull/3825)). The restore refusal field is now `blockedRecordId` ([#3986](https://github.com/pipeshub-ai/pipeshub-ai/pull/3986) — @siddhant-pipeshub). The whole checklist is tested end to end ([#3853](https://github.com/pipeshub-ai/pipeshub-ai/pull/3853), [#3885](https://github.com/pipeshub-ai/pipeshub-ai/pull/3885)). With the setting off, deletes work as they did before. (@shekharkadyan)

### Agents can search the knowledge graph

A new `entities` vector collection holds one point for each taxonomy node, record title and record group. It is written by the indexing pipeline, and every result is permission-checked against the graph. Agents get `search_entities` and `find_records_by_entity`, and `search` accepts `entity_ids`. So an agent can go from "what's tagged Legal" to the records themselves. Extracted categories, topics and languages now resolve to one canonical node per org ([#3308](https://github.com/pipeshub-ai/pipeshub-ai/pull/3308), [#3729](https://github.com/pipeshub-ai/pipeshub-ai/pull/3729) — @tushar1245). Follow-up phases add these:

- rebuilding the entity index from the graph ([#3759](https://github.com/pipeshub-ai/pipeshub-ai/pull/3759))
- org-scoped aliases ([#3762](https://github.com/pipeshub-ai/pipeshub-ai/pull/3762))
- a reversible merge of duplicate taxonomy nodes ([#3767](https://github.com/pipeshub-ai/pipeshub-ai/pull/3767))
- retried entity cleanup when a connector is deleted ([#3769](https://github.com/pipeshub-ai/pipeshub-ai/pull/3769))
- the permission check inside the graph query ([#3770](https://github.com/pipeshub-ai/pipeshub-ai/pull/3770))
- concurrent enrichment and alias healing ([#3771](https://github.com/pipeshub-ai/pipeshub-ai/pull/3771))
- an entity-resolution eval ([#3772](https://github.com/pipeshub-ai/pipeshub-ai/pull/3772))
- top-3 merge candidates ([#3773](https://github.com/pipeshub-ai/pipeshub-ai/pull/3773))
- further fixes ([#3757](https://github.com/pipeshub-ai/pipeshub-ai/pull/3757), [#4019](https://github.com/pipeshub-ai/pipeshub-ai/pull/4019)) — all @abhishekgml1991

There is now one entities processor per org, shared across knowledge bases ([#3730](https://github.com/pipeshub-ai/pipeshub-ai/pull/3730), [#3785](https://github.com/pipeshub-ai/pipeshub-ai/pull/3785) — @vishwjeet-pawar03). The entity store follows the org's current embedding model ([#3877](https://github.com/pipeshub-ai/pipeshub-ai/pull/3877)). "Delete all embeddings" keeps the entity index, and refills it if it is empty ([#3935](https://github.com/pipeshub-ai/pipeshub-ai/pull/3935)). The embedding-change guard counts only records ([#3858](https://github.com/pipeshub-ai/pipeshub-ai/pull/3858)). Each record keeps its own extracted labels ([#4006](https://github.com/pipeshub-ai/pipeshub-ai/pull/4006)), and an exact issue-key lookup works through the whole resolver ([#4024](https://github.com/pipeshub-ai/pipeshub-ai/pull/4024)). Taxonomy edges are removed on every ArangoDB delete ([#4007](https://github.com/pipeshub-ai/pipeshub-ai/pull/4007) — @abhishek-pipeshub). Two records that enrich the same new topic no longer fail one of them ([#3798](https://github.com/pipeshub-ai/pipeshub-ai/pull/3798)).

### AI models: discovery, multi-model add, and prompt caching

Admins can fetch a provider's model list and add several models in one step, in settings and in onboarding. Each model is checked and saved on its own. Models that pass are kept, and failed ones can be retried. Rotating the key updates every model on the same connection. The release also adds an optional OpenAI base URL and OpenAI-compatible image, speech-to-text and text-to-speech models. Configured models are listed at an OpenAI-compatible `GET /v1/models` ([#4012](https://github.com/pipeshub-ai/pipeshub-ai/pull/4012), [#4054](https://github.com/pipeshub-ai/pipeshub-ai/pull/4054) — @abhishekgml1991).

The agent loop now uses provider prompt caching for the prompt and the tool definitions: Anthropic breakpoints, Bedrock cache points, and OpenAI/Azure `prompt_cache_key`. The prompt prefix also stays the same from turn to turn, so the cache can be reused. It is on by default and controlled by `PIPESHUB_PROMPT_CACHE` ([#4038](https://github.com/pipeshub-ai/pipeshub-ai/pull/4038) — @abhishek-pipeshub). A model can carry its own default reasoning effort, which the chat picker shows ([#3828](https://github.com/pipeshub-ai/pipeshub-ai/pull/3828), [#3837](https://github.com/pipeshub-ai/pipeshub-ai/pull/3837)).

### A locked-down code sandbox and MCP

The sandbox and MCP changes below affect how operators deploy.

- **Docker access:** The app container no longer mounts the Docker socket. A new `docker-socket-proxy` service holds it and allows only sandbox-image containers with no privileged mode, binds or host namespaces. The app now runs as uid 1000 and keeps its existing paths ([#3782](https://github.com/pipeshub-ai/pipeshub-ai/pull/3782), [#3811](https://github.com/pipeshub-ai/pipeshub-ai/pull/3811), [#3816](https://github.com/pipeshub-ai/pipeshub-ai/pull/3816), [#3820](https://github.com/pipeshub-ai/pipeshub-ai/pull/3820)). The Helm DinD sandbox goes through the same proxy ([#3888](https://github.com/pipeshub-ai/pipeshub-ai/pull/3888) — @abhishekgml1991).
- **Network:** Sandbox code runs with the network **off** by default, and when it is on, egress goes through a firewall ([#3780](https://github.com/pipeshub-ai/pipeshub-ai/pull/3780)).
- **Sandbox mode:** An unset or unknown `SANDBOX_MODE` now fails closed ([#3725](https://github.com/pipeshub-ai/pipeshub-ai/pull/3725) — @rish231294). `local` mode requires `SANDBOX_ALLOW_LOCAL=true` ([#3803](https://github.com/pipeshub-ai/pipeshub-ai/pull/3803)). Symlink tar members are dropped, and the sandbox user and file-size limit are pinned ([#3810](https://github.com/pipeshub-ai/pipeshub-ai/pull/3810)). All of these are by @vishwjeet-pawar03 unless noted.
- **MCP:** Custom STDIO MCP servers run only when the operator sets `MCP_ALLOW_CUSTOM_STDIO=true` (Helm: `config.mcpAllowCustomStdio: true`), and catalog commands are pinned ([#3887](https://github.com/pipeshub-ai/pipeshub-ai/pull/3887) — @abhishekgml1991).

A long-running gap is closed. Many connectors kept records whose items had been deleted at the source, or that a narrowed filter now left out. This release fixes that for these connectors:

- Zammad ([#3706](https://github.com/pipeshub-ai/pipeshub-ai/pull/3706))
- Nextcloud ([#3707](https://github.com/pipeshub-ai/pipeshub-ai/pull/3707))
- S3-style object stores, including the "Not in" filters ([#3708](https://github.com/pipeshub-ai/pipeshub-ai/pull/3708), [#3716](https://github.com/pipeshub-ai/pipeshub-ai/pull/3716), [#3717](https://github.com/pipeshub-ai/pipeshub-ai/pull/3717))
- Google Drive Workspace ([#3709](https://github.com/pipeshub-ai/pipeshub-ai/pull/3709))
- Web ([#3712](https://github.com/pipeshub-ai/pipeshub-ai/pull/3712))
- Jira personal ([#3934](https://github.com/pipeshub-ai/pipeshub-ai/pull/3934)), and Jira on Free plans, which refuse the audit log ([#3875](https://github.com/pipeshub-ai/pipeshub-ai/pull/3875), [#3905](https://github.com/pipeshub-ai/pipeshub-ai/pull/3905))
- Snowflake ([#3688](https://github.com/pipeshub-ai/pipeshub-ai/pull/3688))

Deletes also publish their vector cleanup ([#3720](https://github.com/pipeshub-ai/pipeshub-ai/pull/3720)). They remove blob files and storage documents too, and keep content that something else still shares ([#3694](https://github.com/pipeshub-ai/pipeshub-ai/pull/3694)). When a connector or KB is deleted, shared deduplicated content is handed over instead of being deleted and rebuilt, and records whose deduplicated stored content was deleted are healed ([#4020](https://github.com/pipeshub-ai/pipeshub-ai/pull/4020), [#4021](https://github.com/pipeshub-ai/pipeshub-ai/pull/4021) — @abhishekgml1991). A scenario matrix now covers incremental, full, filter, indexing and scheduled sync across 20 connectors ([#3699](https://github.com/pipeshub-ai/pipeshub-ai/pull/3699)).

### Indexing: recorded lanes instead of hashed ones, and less work per record

A community user reported that their Slack connector waited behind about 200,000 GitLab events, because both connectors hashed to the same Redis Streams lane. Each connector is now given the least-loaded lane of the pool (`FAIR_SCHEDULING_LANE_COUNT`, 8 by default), recorded when the connector is created (a connector that existed before the upgrade gets its lane on its first publish), freed when it is deleted, and separated once if two collide. `FAIR_SCHEDULING_LANE_ASSIGNMENT` now defaults to `assigned` on Redis ([#3979](https://github.com/pipeshub-ai/pipeshub-ai/pull/3979), [#3980](https://github.com/pipeshub-ai/pipeshub-ai/pull/3980), [#3982](https://github.com/pipeshub-ai/pipeshub-ai/pull/3982)). On Kafka, a connector at its cap no longer holds up the connectors that share its partition ([#3977](https://github.com/pipeshub-ai/pipeshub-ai/pull/3977)). Queued events of a connector that was turned off or removed are settled as they are read ([#3976](https://github.com/pipeshub-ai/pipeshub-ai/pull/3976)). Turning a connector back on re-queues what pausing it parked ([#4026](https://github.com/pipeshub-ai/pipeshub-ai/pull/4026)). A rate-limited item waits for the reset instead of failing ([#4039](https://github.com/pipeshub-ai/pipeshub-ai/pull/4039)).

There is also less work per record. Extraction is sent only what it reads, and each saved record is encoded once ([#4047](https://github.com/pipeshub-ai/pipeshub-ai/pull/4047)). Each record needs fewer graph queries, and background sweeps are limited to a tenth of a busy loop ([#4048](https://github.com/pipeshub-ai/pipeshub-ai/pull/4048)). Qdrant upserts are sent as a Batch ([#4043](https://github.com/pipeshub-ai/pipeshub-ai/pull/4043)). Large-file parsing stays off the event loop ([#3945](https://github.com/pipeshub-ai/pipeshub-ai/pull/3945)).

### An All Artifacts gallery, and queued email

The new **All Artifacts (Beta)** gallery lists the artifacts a user can access. Users can preview them, download them and switch between versions, and artifacts no longer mix into All Records ([#3427](https://github.com/pipeshub-ai/pipeshub-ai/pull/3427)). The gallery renders PPTX files ([#4056](https://github.com/pipeshub-ai/pipeshub-ai/pull/4056)) and gets apply and clear controls for its filters ([#4058](https://github.com/pipeshub-ai/pipeshub-ai/pull/4058)) — all @abhishekgml1991. Invite emails are no longer sent during the HTTP request. They go out through the message broker, and a background consumer sends them over pooled SMTP ([#2906](https://github.com/pipeshub-ai/pipeshub-ai/pull/2906) — @anupPradhan0). The mail consumer is fixed so it does not send duplicates or lose a send ([#3743](https://github.com/pipeshub-ai/pipeshub-ai/pull/3743) — @abhishekgml1991).
