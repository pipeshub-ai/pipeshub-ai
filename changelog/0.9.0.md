# 0.9.0 — Projects, service accounts and device-code login arrive, with SMB and Drupal Wiki connectors

**Released:** September 28, 2026 · **Channel:** Stable · **Tag:** [`v0.9.0`](https://github.com/pipeshub-ai/pipeshub-ai/releases/tag/v0.9.0)

0.9.0 is a large release: about 290 merged PRs since 0.8.0. Three things are new for people who use PipesHub. Projects give a team a shared place for chats and the knowledge behind them. Automation gets an identity of its own, through service accounts, service tokens and a device-code login for coding agents. And the connector fleet gains SMB 2/3, SMB1/CIFS and Drupal Wiki, a "Folders" sync filter for the object stores, and personal-access-token setup for GitHub Teams and GitLab.

Most of the remaining work is about being correct under failure. A read that fails is no longer taken for "nothing there", so a database restart can no longer look like a deletion; domain events go through an outbox, so a broker outage delays them instead of losing them; and errors across chat, sign-in, uploads and indexing now say what happened in plain words. A large share of the PRs are behaviour tests against real or simulated services, and the bugs those tests found are fixed in the same PRs.

## Breaking changes & upgrade notes

- **The storage service no longer accepts user tokens.** `/api/v1/document/*` (download, buffer, upload, uploadNextVersion, rollBack, directUpload, delete, metadata, isModified) checked only that the document was in the caller's org, never the caller's record permissions, so any signed-in employee (or a PAT/OAuth app with `kb:read`/`kb:write`) who learned a document id could read, overwrite, roll back or delete files in private knowledge bases and other users' chat artifacts. Those routes are removed and answer 404; only the service-token `/api/v1/document/internal/*` routes remain. API clients should use the permission-checked Knowledge Base routes instead, e.g. `GET /api/v1/knowledgeBase/stream/record/{recordId}`. User-facing links the backend generates (agent artifacts, SQL query CSV exports on local storage) now point at that stream route, and SQL result exports are saved as versioned artifact records owned by the requesting user. The agent tool `get_record_download_url` now checks the user's access to the record before minting an S3/Azure signed URL. Chat messages persisted before this change that embed a `/api/v1/document/{id}/download` link (local storage CSV exports) no longer download ([#3593](https://github.com/pipeshub-ai/pipeshub-ai/pull/3593) — @abhishekgml1991).
- **Each organization is limited to 5 admins**, counting pending admin invites. Promoting, inviting or editing an invite past the cap is refused with a 400. ([#3284](https://github.com/pipeshub-ai/pipeshub-ai/pull/3284) — @Pranjal-wq).
- **Sign-in no longer reveals whether an email has an account.** An unknown email gets the same status and message as a wrong password or code, and a locked account is refused with that same answer ([#3529](https://github.com/pipeshub-ai/pipeshub-ai/pull/3529)). SAML sent to the normal sign-in endpoint is answered instead of hanging ([#3531](https://github.com/pipeshub-ai/pipeshub-ai/pull/3531)), and a multi-step sign-in policy that includes SAML is refused on save ([#3510](https://github.com/pipeshub-ai/pipeshub-ai/pull/3510)). Clients that matched on the old "blocked" or "no such user" answers need to change.
- **An auto-blocked account loses its active sessions** at once ([#3277](https://github.com/pipeshub-ai/pipeshub-ai/pull/3277) — @krishsingh120), and **only the account owner can change its email address** ([#3272](https://github.com/pipeshub-ai/pipeshub-ai/pull/3272)).
- **Web-search API keys are no longer sent to members** in configuration responses ([#3532](https://github.com/pipeshub-ai/pipeshub-ai/pull/3532)).
- **Keyword scoring changes on existing collections.** IDF is turned on in place the first time a collection is written to, or when the query service starts; stored data is not rewritten and no re-index is needed. Expect hybrid search rankings to shift ([#3488](https://github.com/pipeshub-ai/pipeshub-ai/pull/3488)).
- **GitLab requires `https` for OAuth tokens as well as personal access tokens**; plain `http` needs an explicit opt-in ([#3362](https://github.com/pipeshub-ai/pipeshub-ai/pull/3362)).
- **Each GitHub and GitLab connector instance (personal and team) now syncs exactly one repository.** The Repository filter is a single choice, and an instance cannot be saved or enabled without one valid repository. A stored configuration with no repository, two or more, or a `not_in` operator is refused with the reason, so an instance that synced several repositories must be split into one instance per repository ([#3251](https://github.com/pipeshub-ai/pipeshub-ai/pull/3251) — @darshangodase).
- **`install.sh --upgrade` now honours `--version` and `PIPESHUB_VERSION`** ([#3175](https://github.com/pipeshub-ai/pipeshub-ai/pull/3175)).

## Highlights

### Projects

Projects are a shared workspace for conversations. A project has members, a knowledge base of its own, and chats that are either private or visible to the whole project; projects can be pinned and archived ([#3304](https://github.com/pipeshub-ai/pipeshub-ai/pull/3304) — @abhishekgml1991). The project workspace was redesigned and gained an archived-projects tab ([#3426](https://github.com/pipeshub-ai/pipeshub-ai/pull/3426) — @vanshg685), and opening a project now lands on the project page rather than a chat ([#3438](https://github.com/pipeshub-ai/pipeshub-ai/pull/3438) — @tushar1245). Project delete is idempotent and unlinking a conversation sends explicit nulls ([#3355](https://github.com/pipeshub-ai/pipeshub-ai/pull/3355) — @shekharkadyan), and OAuth apps can be granted the Projects and MCP server scopes ([#3344](https://github.com/pipeshub-ai/pipeshub-ai/pull/3344) — @shekharkadyan).

### Identities for automation: service accounts, service tokens and device-code login

Until now, a script could only read from PipesHub by borrowing a person: a `client_credentials` token acts as whoever created the OAuth app, with that person's document access and role. A **service account** is an ordinary user record with `kind: 'service'` that nobody signs in as, so the existing permission graph decides what it can see ([#3420](https://github.com/pipeshub-ai/pipeshub-ai/pull/3420) — @shekharkadyan). A **service token** is how a script authenticates as one: an administrator mints it for the account, scopes must be chosen explicitly, and `agent:execute` is refused ([#3422](https://github.com/pipeshub-ai/pipeshub-ai/pull/3422) — @shekharkadyan). The token screen now says what each permission allows ([#3606](https://github.com/pipeshub-ai/pipeshub-ai/pull/3606)), and the OAuth app screen warns that client-credentials tokens inherit their creator's access and admin role ([#3417](https://github.com/pipeshub-ai/pipeshub-ai/pull/3417)).

For coding agents that should act as a signed-in person, there is now a **device-code login**: the agent starts a login, a person already signed in to PipesHub approves it, and the agent receives that person's token. The same PR adds optional app self-registration and a smaller "eval" Docker install for trying search and chat on a laptop ([#3197](https://github.com/pipeshub-ai/pipeshub-ai/pull/3197) — @shekharkadyan). An account deleted after approving gets no tokens ([#3361](https://github.com/pipeshub-ai/pipeshub-ai/pull/3361)).

### New connectors and connector options

- **SMB 2/3 and SMB1/CIFS network shares** — two connectors that share one walker and record mapper, so both write the same file-share graph model ([#3533](https://github.com/pipeshub-ai/pipeshub-ai/pull/3533) — @abhishekgml1991).
- **Drupal Wiki (KontextWork)** — syncs users, groups, spaces, pages and attachments, with per-space permissions and page hierarchy. This first version does not remove pages deleted in the wiki ([#3466](https://github.com/pipeshub-ai/pipeshub-ai/pull/3466) — @darshangodase).
- **GitHub Teams and GitLab** can be configured with a personal access token instead of OAuth ([#3325](https://github.com/pipeshub-ai/pipeshub-ai/pull/3325) — @shekharkadyan).
- **S3, MinIO, GCS, Azure Blob and Azure Files** get a "Folders" sync filter ([#3340](https://github.com/pipeshub-ai/pipeshub-ai/pull/3340) — @shekharkadyan).
- **Team connectors authenticated as a different account** — when the account a connector signs in with has a different email from the PipesHub user who created it, the creator could see none of the connector's records. Jira and Confluence (Cloud and Data Center), GitHub Teams, GitLab and Linear now link the creator to that account for that connector only ([#3313](https://github.com/pipeshub-ai/pipeshub-ai/pull/3313) — @darshangodase).

### A failed read is no longer a deletion

Several code paths treated "the lookup failed" the same as "there is nothing there", and then acted on it. During a graph or database restart that could delete a live record's vectors, drop a mapping, or create a duplicate group. Each of those paths now raises instead: an unreadable graph or connector is not a deleted record or connector ([#3444](https://github.com/pipeshub-ai/pipeshub-ai/pull/3444), [#3458](https://github.com/pipeshub-ai/pipeshub-ai/pull/3458), [#3463](https://github.com/pipeshub-ai/pipeshub-ai/pull/3463), [#3474](https://github.com/pipeshub-ai/pipeshub-ai/pull/3474)), a failed listing is not an empty one ([#3416](https://github.com/pipeshub-ai/pipeshub-ai/pull/3416), [#3472](https://github.com/pipeshub-ai/pipeshub-ai/pull/3472), [#3477](https://github.com/pipeshub-ai/pipeshub-ai/pull/3477)), a failed lookup no longer creates a duplicate group or role or reads as "no such record" ([#3453](https://github.com/pipeshub-ai/pipeshub-ai/pull/3453), [#3479](https://github.com/pipeshub-ai/pipeshub-ai/pull/3479)), a vector-store manifest is never replaced by one that could not be read ([#3480](https://github.com/pipeshub-ai/pipeshub-ai/pull/3480)), and Jira and Confluence never treat a failed read as "no access" or skip a failed sync window ([#3521](https://github.com/pipeshub-ai/pipeshub-ai/pull/3521), [#3528](https://github.com/pipeshub-ai/pipeshub-ai/pull/3528)). Search now says so when permissions cannot be read, instead of answering "no documents" ([#3485](https://github.com/pipeshub-ai/pipeshub-ai/pull/3485)). All by @shekharkadyan.

In the same spirit, domain events from the Node.js API (users, orgs, service accounts, knowledge base relations, connectors) now go through an **outbox**: the event is written to MongoDB and a dispatcher delivers it, so a broker outage makes delivery late rather than lost. Previously the failure was logged and the caller was told the write had worked, which could leave a user who exists but sees nothing ([#3445](https://github.com/pipeshub-ai/pipeshub-ai/pull/3445) — @shekharkadyan).

### Search: permissions pushed into the vector query, and better keyword ranking

Every search used to start by asking the graph for every record the user can see, often tens of thousands of ids, and passing that list to the vector store. Search now fetches the user's accessible *containers* (connectors, record groups) and filters on those, falling back to record ids only for connectors with per-record permissions. The new path is behind a feature flag ([#3230](https://github.com/pipeshub-ai/pipeshub-ai/pull/3230) — @shrikantNemiwal1). Hybrid search also ranks better: the BM25 sparse leg now applies IDF, so a rare name outweighs a common word ([#3488](https://github.com/pipeshub-ai/pipeshub-ai/pull/3488) — @abhishekgml1991). Deleting a connector or collection removes its embeddings by membership instead of shipping every record id in one message, which failed past roughly 25,000 records on Kafka ([#3159](https://github.com/pipeshub-ai/pipeshub-ai/pull/3159) — @shrikantNemiwal1).

### Chat: stop generation, working non-streaming endpoints, and custom skills

A running answer can be stopped ([#3301](https://github.com/pipeshub-ai/pipeshub-ai/pull/3301) — @abhishekgml1991), with follow-up fixes so a reload no longer shows an empty "Stopped" reply, the question stays on screen when Stop lands first, and a run the server aborts ends the turn cleanly ([#3329](https://github.com/pipeshub-ai/pipeshub-ai/pull/3329), [#3464](https://github.com/pipeshub-ai/pipeshub-ai/pull/3464), [#3511](https://github.com/pipeshub-ai/pipeshub-ai/pull/3511)). The four JSON (non-SSE) chat routes for conversations and agent conversations, which API callers use, were broken and work again ([#3591](https://github.com/pipeshub-ai/pipeshub-ai/pull/3591) — @abhishekgml1991). Custom skills can be enabled behind a feature flag, with prompt tuning and fixes ([#3331](https://github.com/pipeshub-ai/pipeshub-ai/pull/3331), [#3338](https://github.com/pipeshub-ai/pipeshub-ai/pull/3338), [#3378](https://github.com/pipeshub-ai/pipeshub-ai/pull/3378) — @abhishekgml1991; [#3484](https://github.com/pipeshub-ai/pipeshub-ai/pull/3484) — @tushar1245), and the Google Drive, Gmail and Calendar MCP servers are registered in the catalog ([#3478](https://github.com/pipeshub-ai/pipeshub-ai/pull/3478) — @tushar1245).

### Errors that say what happened

A sweep across the product replaces raw exception text and generic 500s with messages a person can act on: sign-in, uploads, validation and model setup ([#3389](https://github.com/pipeshub-ai/pipeshub-ai/pull/3389)), chat and agent chat ([#3390](https://github.com/pipeshub-ai/pipeshub-ai/pull/3390)), indexing failures ([#3388](https://github.com/pipeshub-ai/pipeshub-ai/pull/3388)), speech ([#3407](https://github.com/pipeshub-ai/pipeshub-ai/pull/3407)), storage ([#3391](https://github.com/pipeshub-ai/pipeshub-ai/pull/3391)), and service failures in general ([#3386](https://github.com/pipeshub-ai/pipeshub-ai/pull/3386), [#3399](https://github.com/pipeshub-ai/pipeshub-ai/pull/3399), [#3401](https://github.com/pipeshub-ai/pipeshub-ai/pull/3401)). "Try again" errors stay retryable instead of becoming 500s ([#3380](https://github.com/pipeshub-ai/pipeshub-ai/pull/3380)), a missing language model is named instead of failing records with `'llm'` ([#3381](https://github.com/pipeshub-ai/pipeshub-ai/pull/3381)), and a 500 no longer repeats what the failure said ([#3419](https://github.com/pipeshub-ai/pipeshub-ai/pull/3419)). All by @shekharkadyan.
