# 0.1.0-alpha — The founding release: enterprise search platform, RAG pipeline, and a fleet of connectors from zero

**Released:** October 28, 2025 · **Channel:** Alpha · **Tag:** [`v0.1.0-alpha`](https://github.com/pipeshub-ai/pipeshub-ai/releases/tag/v0.1.0-alpha)

*This alpha line was finalized as [0.1.0](0.1.0.md).*

This is PipesHub's first public release, and its notes enumerate the project's entire initial development history — nearly 700 merged PRs (#1 through #928). It stands up the whole platform in one release: a Node.js Express API for auth, users, and knowledge bases; Python FastAPI microservices for connectors, indexing, and query/RAG; a React frontend; and a stateful backbone of ArangoDB, Qdrant, MongoDB, Redis, Kafka, and etcd, all shipped as a self-hostable Docker Compose deployment under the Apache 2.0 license ([#357](https://github.com/pipeshub-ai/pipeshub-ai/pull/357) — @abhishek-pipeshub).

Given the founding scope, this changelog takes a thematic view with representative PR citations rather than the usual per-PR accounting; the [GitHub release](https://github.com/pipeshub-ai/pipeshub-ai/releases/tag/v0.1.0-alpha) has the exhaustive list.

## Highlights

### Platform architecture and core services

The initial architecture comes together across the release: an etcd-backed configuration manager ([#11](https://github.com/pipeshub-ai/pipeshub-ai/pull/11) — @khushijainslack, later generalized to any key-value store in [#500](https://github.com/pipeshub-ai/pipeshub-ai/pull/500) — @abhishekgml1991), Kafka-driven async record processing ([#83](https://github.com/pipeshub-ai/pipeshub-ai/pull/83)), ArangoDB graph schema and record permissions ([#8](https://github.com/pipeshub-ai/pipeshub-ai/pull/8) — @rohilbansal-pipeshub), and internal service routes with token-based service auth ([#23](https://github.com/pipeshub-ai/pipeshub-ai/pull/23), [#27](https://github.com/pipeshub-ai/pipeshub-ai/pull/27)). The services tree was restructured into the `backend/` layout that persists today ([#423](https://github.com/pipeshub-ai/pipeshub-ai/pull/423) — @abhishekgml1991), and the connectors service moved to its long-term port 8088 ([#252](https://github.com/pipeshub-ai/pipeshub-ai/pull/252)).

### RAG pipeline: from first Chat API to token-level streaming

The query service grew from an initial Chat API ([#33](https://github.com/pipeshub-ai/pipeshub-ai/pull/33) — @abhishekgml1991) into a full retrieval pipeline: query rewrite and expansion with async API calls ([#66](https://github.com/pipeshub-ai/pipeshub-ai/pull/66)), multi-question query decomposition ([#74](https://github.com/pipeshub-ai/pipeshub-ai/pull/74)), a reranker ([#96](https://github.com/pipeshub-ai/pipeshub-ai/pull/96)), LangGraph orchestration ([#277](https://github.com/pipeshub-ai/pipeshub-ai/pull/277)), and follow-up query transformation ([#420](https://github.com/pipeshub-ai/pipeshub-ai/pull/420)). Answers stream token-by-token end to end — streaming API ([#431](https://github.com/pipeshub-ai/pipeshub-ai/pull/431)), model-native streaming ([#456](https://github.com/pipeshub-ai/pipeshub-ai/pull/456)), citation-safe chunking ([#457](https://github.com/pipeshub-ai/pipeshub-ai/pull/457)), and frontend streaming support ([#451](https://github.com/pipeshub-ai/pipeshub-ai/pull/451) — @vishwjeet-pawar03). Normalized citations with web URLs ([#438](https://github.com/pipeshub-ai/pipeshub-ai/pull/438), [#360](https://github.com/pipeshub-ai/pipeshub-ai/pull/360)) and a low-latency Quick mode as the default ([#458](https://github.com/pipeshub-ai/pipeshub-ai/pull/458), [#645](https://github.com/pipeshub-ai/pipeshub-ai/pull/645)) round out the pipeline.

### Bring-your-own-model: 10+ LLM and embedding providers

Model support expanded from OpenAI-only to a broad provider matrix: Gemini ([#114](https://github.com/pipeshub-ai/pipeshub-ai/pull/114)), Anthropic ([#120](https://github.com/pipeshub-ai/pipeshub-ai/pull/120) — @abhishek-pipeshub), AWS Bedrock ([#128](https://github.com/pipeshub-ai/pipeshub-ai/pull/128), [#506](https://github.com/pipeshub-ai/pipeshub-ai/pull/506)), Ollama for local models ([#313](https://github.com/pipeshub-ai/pipeshub-ai/pull/313), [#475](https://github.com/pipeshub-ai/pipeshub-ai/pull/475)), any OpenAI-compatible endpoint ([#346](https://github.com/pipeshub-ai/pipeshub-ai/pull/346)), and xAI, Mistral, Cohere, Together, Groq, and Fireworks in one refactor that made adding new providers trivial ([#483](https://github.com/pipeshub-ai/pipeshub-ai/pull/483), [#484](https://github.com/pipeshub-ai/pipeshub-ai/pull/484) — @abhishekgml1991). Embeddings got the same treatment: Cohere and Gemini ([#338](https://github.com/pipeshub-ai/pipeshub-ai/pull/338)), Ollama ([#480](https://github.com/pipeshub-ai/pipeshub-ai/pull/480)), OpenAI-compatible APIs ([#413](https://github.com/pipeshub-ai/pipeshub-ai/pull/413)), and Voyage, JinaAI, and Mistral ([#485](https://github.com/pipeshub-ai/pipeshub-ai/pull/485)).

### Connector fleet and data-source SDK

First-class connectors arrived for Google Workspace (Drive and Gmail with webhooks, watches, and resync — [#250](https://github.com/pipeshub-ai/pipeshub-ai/pull/250) — @rohilbansal-pipeshub), OneDrive ([#594](https://github.com/pipeshub-ai/pipeshub-ai/pull/594)), SharePoint Online ([#635](https://github.com/pipeshub-ai/pipeshub-ai/pull/635)), Confluence Cloud ([#785](https://github.com/pipeshub-ai/pipeshub-ai/pull/785)), Jira ([#542](https://github.com/pipeshub-ai/pipeshub-ai/pull/542)), Slack ([#546](https://github.com/pipeshub-ai/pipeshub-ai/pull/546) — @kaushal1999), Outlook ([#802](https://github.com/pipeshub-ai/pipeshub-ai/pull/802) — @shrikantNemiwal1), Dropbox ([#808](https://github.com/pipeshub-ai/pipeshub-ai/pull/808) — @R0gue-one), and web pages ([#928](https://github.com/pipeshub-ai/pipeshub-ai/pull/928)). Underneath, an OpenAPI-driven client generator ([#580](https://github.com/pipeshub-ai/pipeshub-ai/pull/580), [#584](https://github.com/pipeshub-ai/pipeshub-ai/pull/584) — @rish231294) and a connector registry ([#653](https://github.com/pipeshub-ai/pipeshub-ai/pull/653) — @vishwjeet-pawar03) enabled a wave of community-built data sources: GitHub ([#771](https://github.com/pipeshub-ai/pipeshub-ai/pull/771) — @uncleSlayer), GitLab ([#795](https://github.com/pipeshub-ai/pipeshub-ai/pull/795)), Notion ([#663](https://github.com/pipeshub-ai/pipeshub-ai/pull/663)), S3 ([#694](https://github.com/pipeshub-ai/pipeshub-ai/pull/694)), Azure Blob ([#697](https://github.com/pipeshub-ai/pipeshub-ai/pull/697)), Box ([#703](https://github.com/pipeshub-ai/pipeshub-ai/pull/703)), Linear ([#740](https://github.com/pipeshub-ai/pipeshub-ai/pull/740)), Airtable ([#746](https://github.com/pipeshub-ai/pipeshub-ai/pull/746)), Zendesk ([#751](https://github.com/pipeshub-ai/pipeshub-ai/pull/751)), Discord ([#815](https://github.com/pipeshub-ai/pipeshub-ai/pull/815) — @MinuteHanD), Freshdesk ([#821](https://github.com/pipeshub-ai/pipeshub-ai/pull/821)), LinkedIn ([#826](https://github.com/pipeshub-ai/pipeshub-ai/pull/826) — @darshangodase), PagerDuty ([#912](https://github.com/pipeshub-ai/pipeshub-ai/pull/912)), BookStack ([#823](https://github.com/pipeshub-ai/pipeshub-ai/pull/823)), ServiceNow ([#829](https://github.com/pipeshub-ai/pipeshub-ai/pull/829)), Evernote ([#852](https://github.com/pipeshub-ai/pipeshub-ai/pull/852)), Asana ([#834](https://github.com/pipeshub-ai/pipeshub-ai/pull/834)), and Zammad ([#902](https://github.com/pipeshub-ai/pipeshub-ai/pull/902)), plus a connector integration playbook ([#850](https://github.com/pipeshub-ai/pipeshub-ai/pull/850) — @shrikantNemiwal1) and generic OAuth support ([#396](https://github.com/pipeshub-ai/pipeshub-ai/pull/396) — @ShawnSack).

### Blocks-based document parsing and indexing

Indexing converged on a unified blocks schema ([#406](https://github.com/pipeshub-ai/pipeshub-ai/pull/406), [#648](https://github.com/pipeshub-ai/pipeshub-ai/pull/648) — @kaushal1999) with format-specific converters for DOCX ([#679](https://github.com/pipeshub-ai/pipeshub-ai/pull/679)), Excel ([#684](https://github.com/pipeshub-ai/pipeshub-ai/pull/684)), Gmail ([#698](https://github.com/pipeshub-ai/pipeshub-ai/pull/698)), and Slack mrkdwn ([#553](https://github.com/pipeshub-ai/pipeshub-ai/pull/553)). Image indexing and multimodal support landed ([#863](https://github.com/pipeshub-ai/pipeshub-ai/pull/863), [#688](https://github.com/pipeshub-ai/pipeshub-ai/pull/688) — @vishwjeet-pawar03), Docling handles complex PDFs with thread-safety and slowness workarounds ([#909](https://github.com/pipeshub-ai/pipeshub-ai/pull/909), [#739](https://github.com/pipeshub-ai/pipeshub-ai/pull/739)), vector points are quantized to Uint8 to cut Qdrant memory ([#468](https://github.com/pipeshub-ai/pipeshub-ai/pull/468)), and records stuck in-progress after a crash are recovered ([#814](https://github.com/pipeshub-ai/pipeshub-ai/pull/814)).

### Agents and enterprise tools

Beyond RAG, the release seeds the agent runtime: agent tools ([#522](https://github.com/pipeshub-ai/pipeshub-ai/pull/522) — @rish231294), Google enterprise tools ([#535](https://github.com/pipeshub-ai/pipeshub-ai/pull/535)), a no-code agent builder ([#600](https://github.com/pipeshub-ai/pipeshub-ai/pull/600) — @vishwjeet-pawar03), agentic RAG streaming ([#463](https://github.com/pipeshub-ai/pipeshub-ai/pull/463)), agent citation handling ([#791](https://github.com/pipeshub-ai/pipeshub-ai/pull/791) — @kaushal1999), and improved tool calling ([#845](https://github.com/pipeshub-ai/pipeshub-ai/pull/845)).

### Knowledge bases, search UI, and auth

Users get per-org knowledge bases with multi-KB support ([#286](https://github.com/pipeshub-ai/pipeshub-ai/pull/286), [#487](https://github.com/pipeshub-ai/pipeshub-ai/pull/487) — @vishwjeet-pawar03), in-app viewers with citation highlighting for PDF, DOCX, Excel, HTML, text, and Markdown ([#154](https://github.com/pipeshub-ai/pipeshub-ai/pull/154), [#168](https://github.com/pipeshub-ai/pipeshub-ai/pull/168)), knowledge search with filters ([#334](https://github.com/pipeshub-ai/pipeshub-ai/pull/334)), dark mode ([#364](https://github.com/pipeshub-ai/pipeshub-ai/pull/364), [#417](https://github.com/pipeshub-ai/pipeshub-ai/pull/417)), and document summaries ([#268](https://github.com/pipeshub-ai/pipeshub-ai/pull/268) — @rohilbansal-pipeshub). On the auth side: SAML SSO ([#105](https://github.com/pipeshub-ai/pipeshub-ai/pull/105) — @khushijainslack), JWT secret handling ([#144](https://github.com/pipeshub-ai/pipeshub-ai/pull/144)), secret key hashing ([#262](https://github.com/pipeshub-ai/pipeshub-ai/pull/262)), Microsoft MSAL login fixes ([#558](https://github.com/pipeshub-ai/pipeshub-ai/pull/558)), and a run of dependency security patches (multer, samlify, pdf.js, xlsx, Vite — [#388](https://github.com/pipeshub-ai/pipeshub-ai/pull/388), [#389](https://github.com/pipeshub-ai/pipeshub-ai/pull/389), [#259](https://github.com/pipeshub-ai/pipeshub-ai/pull/259), [#274](https://github.com/pipeshub-ai/pipeshub-ai/pull/274), [#256](https://github.com/pipeshub-ai/pipeshub-ai/pull/256)).

- Production Docker Compose with simplified config, model downloads baked into images, and slim Python base images ([#178](https://github.com/pipeshub-ai/pipeshub-ai/pull/178), [#290](https://github.com/pipeshub-ai/pipeshub-ai/pull/290), [#143](https://github.com/pipeshub-ai/pipeshub-ai/pull/143), [#918](https://github.com/pipeshub-ai/pipeshub-ai/pull/918), [#474](https://github.com/pipeshub-ai/pipeshub-ai/pull/474)).

- Swagger/OpenAPI docs for storage APIs, Prometheus metrics collection, feature flags, and PostHog analytics ([#93](https://github.com/pipeshub-ai/pipeshub-ai/pull/93), [#246](https://github.com/pipeshub-ai/pipeshub-ai/pull/246), [#865](https://github.com/pipeshub-ai/pipeshub-ai/pull/865), [#839](https://github.com/pipeshub-ai/pipeshub-ai/pull/839) — @jatingaur18).
