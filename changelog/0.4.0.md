# 0.4.0 — Next.js frontend replaces the React UI; GitLab, Salesforce, and Zoom connectors land

**Released:** May 5, 2026 · **Channel:** Stable · **Tag:** [`v0.4.0`](https://github.com/pipeshub-ai/pipeshub-ai/releases/tag/v0.4.0)

A very large release — 380+ merged PRs since 0.3.0. The headline is a complete frontend replacement: the React SPA was rewritten as a Next.js app and the old frontend removed. Around it, the connector fleet grows with GitLab, Salesforce, Zoom, and personal Outlook; the assistant gains web search, a coding sandbox with artifacts, and image/speech model support; and toolsets get a first-class management experience with several new integrations (Redshift, OneDrive, Lumos, Zoom, Salesforce).

For operators, this release adds real deployment flexibility: Redis as an optional message broker in place of Kafka, Windows support, Python 3.12, hot-reloading dev composes, and log rotation. A long tail of fixes hardens chat, citations, knowledge search, and connector sync.

## Breaking changes & upgrade notes

- The legacy React frontend is removed; the Next.js frontend is the only UI ([#2169](https://github.com/pipeshub-ai/pipeshub-ai/pull/2169)).
- Python services moved to Python 3.12 ([#1755](https://github.com/pipeshub-ai/pipeshub-ai/pull/1755)).
- The frontend consolidates on a single backend URL; redundant URL settings were removed ([#1780](https://github.com/pipeshub-ai/pipeshub-ai/pull/1780)).
- The SMTP step was removed from onboarding ([#2180](https://github.com/pipeshub-ai/pipeshub-ai/pull/2180)).
- Unnecessary container ports are no longer exposed, alongside a logs cleanup ([#1890](https://github.com/pipeshub-ai/pipeshub-ai/pull/1890)).
- The backend switched to the new custom MCP server ([#2185](https://github.com/pipeshub-ai/pipeshub-ai/pull/2185)).
- The dev Docker compose now defaults to Neo4j as the graph store ([#2170](https://github.com/pipeshub-ai/pipeshub-ai/pull/2170)).

## Highlights

### The frontend is now Next.js

The React SPA was rewritten as a Next.js application ([#1882](https://github.com/pipeshub-ai/pipeshub-ai/pull/1882) — @abhishek-pipeshub) and, after stabilizing through the beta cycle, the legacy React frontend was removed so the Next.js app is the only UI ([#2169](https://github.com/pipeshub-ai/pipeshub-ai/pull/2169) — @abhishekgml1991). The new frontend has its own build workflow ([#1920](https://github.com/pipeshub-ai/pipeshub-ai/pull/1920)), Turbopack in dev mode ([#1937](https://github.com/pipeshub-ai/pipeshub-ai/pull/1937) — @akshay-pythm), and went through a broad cleanup pass ([#1970](https://github.com/pipeshub-ai/pipeshub-ai/pull/1970)). Much of this release's fix volume is polish on the new UI.

### Coding sandbox, artifacts, and image generation

Conversations can now run code in a sandbox and produce artifacts, backed by a new image-generation model type ([#2031](https://github.com/pipeshub-ai/pipeshub-ai/pull/2031) — @abhishekgml1991), with the sandbox enabled in the production compose ([#2165](https://github.com/pipeshub-ai/pipeshub-ai/pull/2165)). Follow-ups fixed local executor errors ([#2048](https://github.com/pipeshub-ai/pipeshub-ai/pull/2048)), artifact UI issues ([#2050](https://github.com/pipeshub-ai/pipeshub-ai/pull/2050)), rendered PPTX artifacts as PDF with debounced SSE updates ([#2053](https://github.com/pipeshub-ai/pipeshub-ai/pull/2053)), and raised the image-generation timeout ([#2072](https://github.com/pipeshub-ai/pipeshub-ai/pull/2072) — @abhishek-pipeshub). Speech-to-text and text-to-speech model types were added alongside ([#2033](https://github.com/pipeshub-ai/pipeshub-ai/pull/2033)).

### New connectors: GitLab, Salesforce, Zoom, personal Outlook

GitLab connector v1 syncs work items and merge requests (with notes) plus project code files ([#1857](https://github.com/pipeshub-ai/pipeshub-ai/pull/1857) — @jain-ayush-wyld). Salesforce arrives as both a data connector ([#1787](https://github.com/pipeshub-ai/pipeshub-ai/pull/1787)) and an agent toolset ([#1862](https://github.com/pipeshub-ai/pipeshub-ai/pull/1862) — @jatingaur18). Zoom gets a connector ([#1809](https://github.com/pipeshub-ai/pipeshub-ai/pull/1809) — @darshangodase) and a toolset ([#1687](https://github.com/pipeshub-ai/pipeshub-ai/pull/1687) — @jatingaur18), with meeting web/recording URLs and transcript text highlighting ([#1819](https://github.com/pipeshub-ai/pipeshub-ai/pull/1819), [#1820](https://github.com/pipeshub-ai/pipeshub-ai/pull/1820), [#1752](https://github.com/pipeshub-ai/pipeshub-ai/pull/1752)). A personal Outlook connector rounds out the set ([#1756](https://github.com/pipeshub-ai/pipeshub-ai/pull/1756) — @shrikantNemiwal1).

### Toolsets become first-class

Dedicated toolset pages ([#1954](https://github.com/pipeshub-ai/pipeshub-ai/pull/1954) — @vishwjeet-pawar03) with documentation links ([#1997](https://github.com/pipeshub-ai/pipeshub-ai/pull/1997)), plus new toolsets for Redshift ([#1686](https://github.com/pipeshub-ai/pipeshub-ai/pull/1686) — @Ayushman444), OneDrive ([#1926](https://github.com/pipeshub-ai/pipeshub-ai/pull/1926) — @jatingaur18), and Lumos ([#1649](https://github.com/pipeshub-ai/pipeshub-ai/pull/1649) — @vanshg685). Jira and Confluence toolsets/connectors now accept API-token authentication ([#1742](https://github.com/pipeshub-ai/pipeshub-ai/pull/1742) — @darshangodase). A developer-settings page manages OAuth 2.0 apps ([#1913](https://github.com/pipeshub-ai/pipeshub-ai/pull/1913) — @vanshg685), and OAuth apps are visible to non-admin users ([#2138](https://github.com/pipeshub-ai/pipeshub-ai/pull/2138) — @realaashil).

### Web search and deeper agent modes

The assistant gains web search ([#1903](https://github.com/pipeshub-ai/pipeshub-ai/pull/1903) — @kaushal1999), wired into the agent schema and builder UI ([#2125](https://github.com/pipeshub-ai/pipeshub-ai/pull/2125), [#2143](https://github.com/pipeshub-ai/pipeshub-ai/pull/2143), [#2147](https://github.com/pipeshub-ai/pipeshub-ai/pull/2147)). The assistant also gets an agent mode ([#1874](https://github.com/pipeshub-ai/pipeshub-ai/pull/1874) — @tushar1245), the deep agent adds a critic + reflector loop for self-checking answers ([#1739](https://github.com/pipeshub-ai/pipeshub-ai/pull/1739) — @Ayushman444), and the universal agent picks up tools, with built-in tools surfaced in the response prompt ([#2100](https://github.com/pipeshub-ai/pipeshub-ai/pull/2100), [#2059](https://github.com/pipeshub-ai/pipeshub-ai/pull/2059) — @vishwjeet-pawar03).

### Indexing reconciliation and SQL connectors

The indexing pipeline gains reconciliation so documents that drop out mid-pipeline are detected and re-driven, arriving together with SQL connectors ([#1568](https://github.com/pipeshub-ai/pipeshub-ai/pull/1568) — @Ayushman444). Indexing throughput improved in two rounds ([#1692](https://github.com/pipeshub-ai/pipeshub-ai/pull/1692) — @mstcomit, [#1759](https://github.com/pipeshub-ai/pipeshub-ai/pull/1759) — @kaushal1999), Docling parse/OCR worker counts were retuned ([#1773](https://github.com/pipeshub-ai/pipeshub-ai/pull/1773)), and duplicate detection now hashes the latest file content ([#1770](https://github.com/pipeshub-ai/pipeshub-ai/pull/1770) — @kaushal1999).

### More ways to run PipesHub

Redis can now stand in for Kafka as the message broker ([#1823](https://github.com/pipeshub-ai/pipeshub-ai/pull/1823) — @realaashil), Windows is supported ([#1844](https://github.com/pipeshub-ai/pipeshub-ai/pull/1844), [#1833](https://github.com/pipeshub-ai/pipeshub-ai/pull/1833)), and dev composes get hot reloading ([#1746](https://github.com/pipeshub-ai/pipeshub-ai/pull/1746) — @anupPradhan0, [#1782](https://github.com/pipeshub-ai/pipeshub-ai/pull/1782)). Neo4j and Mongo database names are configurable via env ([#1743](https://github.com/pipeshub-ai/pipeshub-ai/pull/1743) — @tushar1245), Docker logs rotate ([#1747](https://github.com/pipeshub-ai/pipeshub-ai/pull/1747)), and `--wait` blocks until the container reports healthy ([#2024](https://github.com/pipeshub-ai/pipeshub-ai/pull/2024)).
