# 0.5.0 — Jira & Confluence go Data Center, agents get real tools, model providers open up

**Released:** July 1, 2026 · **Channel:** Stable · **Tag:** [`v0.5.0`](https://github.com/pipeshub-ai/pipeshub-ai/releases/tag/v0.5.0)

A large stable release: 230+ merged PRs since 0.4.5. The three big stories are enterprise self-hosted reach (full Jira and Confluence Data Center support alongside a rebuilt Confluence content pipeline), agents that can act rather than just answer (Salesforce, Google Drive, storage, and ask-user-question tools), and an open model layer (first-class OpenRouter, LiteLLM proxy, and LM Studio support, plus a dedicated local embedding service).

Operators also get a one-command installation script, an in-app notification service, substantial memory-leak and query-performance fixes across ArangoDB and Qdrant, and a much larger validated OpenAPI surface backing the SDK.

## Highlights

### Jira and Confluence Data Center support

PipesHub connectors now work against self-hosted Atlassian Data Center, not just Cloud. Jira DC lands with application-role, role, group, and permission syncing, comment/attachment handling, and blockgroup parsing through the HTML parser ([#2435](https://github.com/pipeshub-ai/pipeshub-ai/pull/2435), [#2518](https://github.com/pipeshub-ai/pipeshub-ai/pull/2518), [#2645](https://github.com/pipeshub-ai/pipeshub-ai/pull/2645) — @abhishekgml1991, @darshangodase), with follow-up fixes for attachment 404s, search retries, and empty project IDs ([#2511](https://github.com/pipeshub-ai/pipeshub-ai/pull/2511)). Confluence DC support covers personal instances, base URLs, audit logs, permissions, comments, page web URLs, and retrying page/attachment fetches ([#2528](https://github.com/pipeshub-ai/pipeshub-ai/pull/2528), [#2514](https://github.com/pipeshub-ai/pipeshub-ai/pull/2514), [#2520](https://github.com/pipeshub-ai/pipeshub-ai/pull/2520), [#2550](https://github.com/pipeshub-ai/pipeshub-ai/pull/2550) — @shrikantNemiwal1).

### Agents gain action tools

Agents can now do work in external systems: a Salesforce tool (e.g. setting product prices in a pricebook) with connector-level filters ([#2223](https://github.com/pipeshub-ai/pipeshub-ai/pull/2223), [#2193](https://github.com/pipeshub-ai/pipeshub-ai/pull/2193) — @jatingaur18), a Google Drive file tool ([#2210](https://github.com/pipeshub-ai/pipeshub-ai/pull/2210) — @jatingaur18), upload-to-storage and fetch-from-storage tools with a temporary-file flag ([#2299](https://github.com/pipeshub-ai/pipeshub-ai/pull/2299) — @jatingaur18), and an ask-user-question tool so agents can pause and request clarification mid-run ([#2238](https://github.com/pipeshub-ai/pipeshub-ai/pull/2238) — @vanshg685).

### Open model layer: OpenRouter, LiteLLM proxy, LM Studio

First-class provider support for OpenRouter ([#2621](https://github.com/pipeshub-ai/pipeshub-ai/pull/2621)) and for LiteLLM proxy and LM Studio ([#2628](https://github.com/pipeshub-ai/pipeshub-ai/pull/2628) — @abhishekgml1991) makes it easier to route PipesHub at whatever model gateway you already run. Model roles can now be assigned per function ([#2478](https://github.com/pipeshub-ai/pipeshub-ai/pull/2478)), local dense embedding moves into its own service ([#2466](https://github.com/pipeshub-ai/pipeshub-ai/pull/2466)) with fixes for switching embedding models ([#2482](https://github.com/pipeshub-ai/pipeshub-ai/pull/2482)) and a UI warning when the default embedding model is in use ([#2445](https://github.com/pipeshub-ai/pipeshub-ai/pull/2445) — @R0gue-one). Provider APIs got tests and spec coverage ([#2446](https://github.com/pipeshub-ai/pipeshub-ai/pull/2446) — @uncleSlayer), and the MiniMax default model moved to M3 ([#2471](https://github.com/pipeshub-ai/pipeshub-ai/pull/2471) — @octo-patch).

### Document parsing overhaul

New parsers broaden and speed up ingestion: MarkItDown ([#2472](https://github.com/pipeshub-ai/pipeshub-ai/pull/2472) — @abhishekgml1991), pdfplumber for attachments and indexing behind an .env flag ([#2498](https://github.com/pipeshub-ai/pipeshub-ai/pull/2498), [#2548](https://github.com/pipeshub-ai/pipeshub-ai/pull/2548) — @kaushal1999), selectolax for HTML ([#2542](https://github.com/pipeshub-ai/pipeshub-ai/pull/2542)), and an updated markdown-it parser ([#2522](https://github.com/pipeshub-ai/pipeshub-ai/pull/2522) — @jatingaur18). Indexing now covers code files from knowledge bases while restricting to supported code types ([#2589](https://github.com/pipeshub-ai/pipeshub-ai/pull/2589), [#2432](https://github.com/pipeshub-ai/pipeshub-ai/pull/2432)), record summaries are indexed for better retrieval ([#2359](https://github.com/pipeshub-ai/pipeshub-ai/pull/2359) — @kaushal1999), and a blocks validator guards against malformed input, including invalid image blocks ([#2495](https://github.com/pipeshub-ai/pipeshub-ai/pull/2495), [#2618](https://github.com/pipeshub-ai/pipeshub-ai/pull/2618)).

### Confluence content pipeline rebuilt on blocks

The Confluence connector now fetches page content as ADF and parses it into the standard block format the indexing service consumes — comments included — instead of passing raw HTML through ([#2497](https://github.com/pipeshub-ai/pipeshub-ai/pull/2497) — @shrikantNemiwal1). Folder sync was added ([#2220](https://github.com/pipeshub-ai/pipeshub-ai/pull/2220)), and follow-ups refined the format (ADF → HTML → styled view with image handling) and kept older content backward compatible with page streaming ([#2631](https://github.com/pipeshub-ai/pipeshub-ai/pull/2631), [#2638](https://github.com/pipeshub-ai/pipeshub-ai/pull/2638), [#2580](https://github.com/pipeshub-ai/pipeshub-ai/pull/2580)).

### GitLab connector matures

GitLab gets incremental sync ([#2438](https://github.com/pipeshub-ai/pipeshub-ai/pull/2438) — @tushar1245), improved search ([#2379](https://github.com/pipeshub-ai/pipeshub-ai/pull/2379) — @Kushagra1122), repo-tree pagination with batch fetching for code files ([#2422](https://github.com/pipeshub-ai/pipeshub-ai/pull/2422), [#2401](https://github.com/pipeshub-ai/pipeshub-ai/pull/2401)), code-file timestamp backfill ([#2449](https://github.com/pipeshub-ai/pipeshub-ai/pull/2449)), and a major sync speedup from dropping per-file timestamp API calls ([#2443](https://github.com/pipeshub-ai/pipeshub-ai/pull/2443)).

### In-app notification service

A new notification pipeline publishes events from the Python services to Kafka, consumes them in Node.js, and pushes them to the frontend over WebSockets ([#2431](https://github.com/pipeshub-ai/pipeshub-ai/pull/2431) — @R0gue-one). Follow-ups add SharePoint and OneDrive notifications, duplicate suppression, UI polish, and correct attribution of the authenticated user in messages ([#2594](https://github.com/pipeshub-ai/pipeshub-ai/pull/2594), [#2613](https://github.com/pipeshub-ai/pipeshub-ai/pull/2613), [#2538](https://github.com/pipeshub-ai/pipeshub-ai/pull/2538), [#2549](https://github.com/pipeshub-ai/pipeshub-ai/pull/2549), [#2537](https://github.com/pipeshub-ai/pipeshub-ai/pull/2537) — @darshangodase).
