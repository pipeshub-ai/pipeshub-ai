# 0.1.2-alpha — Confluence and SharePoint connectors land, Azure AI models, indexing pipeline overhaul

**Released:** December 2, 2025 · **Channel:** Alpha · **Tag:** [`0.1.2-alpha`](https://github.com/pipeshub-ai/pipeshub-ai/releases/tag/0.1.2-alpha)

*This alpha line was finalized as [0.1.0](0.1.0.md).*

The last alpha before the [beta](0.1.0-beta.md) is the largest of the point releases: 72 merged PRs. Two major connectors — Confluence and SharePoint — graduate to full sync support, Azure-hosted AI models (OpenAI, Claude, Grok, DeepSeek) join the provider list, and the indexing pipeline gets a substantial overhaul: reordered stages, batched embedding writes, faster Qdrant operations, and more file formats converted through the unified blocks schema. The rest is a wide stabilization pass across query, citations, viewers, and the graph layer.

## Highlights

### Confluence connector

Confluence spaces and pages can now be synced and searched as a first-class connector ([#1017](https://github.com/pipeshub-ai/pipeshub-ai/pull/1017) — @shrikantNemiwal1).

### SharePoint connector

SharePoint sync arrives ([#1018](https://github.com/pipeshub-ai/pipeshub-ai/pull/1018) — @R0gue-one), with a display-name typo fix ([#980](https://github.com/pipeshub-ai/pipeshub-ai/pull/980) — @vishwjeet-pawar03).

### Azure AI models and OpenAI-compatible embeddings

Azure-hosted models — OpenAI, Claude, Grok, and DeepSeek — are now supported as LLM providers ([#1048](https://github.com/pipeshub-ai/pipeshub-ai/pull/1048) — @abhishekgml1991), and any OpenAI-compatible embedding endpoint can be configured ([#1033](https://github.com/pipeshub-ai/pipeshub-ai/pull/1033) — @vishwjeet-pawar03). Model configuration also gained explicit context-length settings, used by the query pipeline instead of hard-coded limits ([#1008](https://github.com/pipeshub-ai/pipeshub-ai/pull/1008), [#1059](https://github.com/pipeshub-ai/pipeshub-ai/pull/1059)), and a `max_tokens` attribute for Anthropic models ([#1027](https://github.com/pipeshub-ai/pipeshub-ai/pull/1027) — @kaushal1999).

### Indexing pipeline overhaul

The indexing pipeline was reordered ([#975](https://github.com/pipeshub-ai/pipeshub-ai/pull/975) — @kaushal1999), document additions are now batched ([#982](https://github.com/pipeshub-ai/pipeshub-ai/pull/982)), `create_embeddings` was refactored ([#992](https://github.com/pipeshub-ai/pipeshub-ai/pull/992)), and Qdrant operations were sped up ([#996](https://github.com/pipeshub-ai/pipeshub-ai/pull/996) — @abhishekgml1991). Blocks conversion expanded to more formats: PyMuPDF and Azure Document Intelligence output ([#981](https://github.com/pipeshub-ai/pipeshub-ai/pull/981)), PPT ([#1046](https://github.com/pipeshub-ai/pipeshub-ai/pull/1046) — @jain-ayush-wyld, first contribution), TXT parsed directly as Markdown ([#990](https://github.com/pipeshub-ai/pipeshub-ai/pull/990)), and SVG images in HTML/Markdown ([#954](https://github.com/pipeshub-ai/pipeshub-ai/pull/954)). Deadlock handling in indexing and fixes for empty-record indexing round it out ([#1045](https://github.com/pipeshub-ai/pipeshub-ai/pull/1045) — @kaushal1999), plus a timeout on Docling PDF processing ([#991](https://github.com/pipeshub-ai/pipeshub-ai/pull/991)) and a fix for re-indexing the same document ([#930](https://github.com/pipeshub-ai/pipeshub-ai/pull/930)).

### Platform settings and refreshed branding

A new platform settings page ([#977](https://github.com/pipeshub-ai/pipeshub-ai/pull/977) — @vishwjeet-pawar03), image previews for records ([#1000](https://github.com/pipeshub-ai/pipeshub-ai/pull/1000)), a new logo ([#1006](https://github.com/pipeshub-ai/pipeshub-ai/pull/1006)), and a replaced sign-in page image ([#1031](https://github.com/pipeshub-ai/pipeshub-ai/pull/1031)).

- Query responses that come back malformed now trigger reflection, with a fallback to reflection when JSON parsing fails ([#1020](https://github.com/pipeshub-ai/pipeshub-ai/pull/1020), [#1060](https://github.com/pipeshub-ai/pipeshub-ai/pull/1060) — @kaushal1999).
- Retrieval limit reduced to 400 chunks after a tool call ([#1023](https://github.com/pipeshub-ai/pipeshub-ai/pull/1023) — @kaushal1999) and a confidence-score bug fixed ([#1038](https://github.com/pipeshub-ai/pipeshub-ai/pull/1038) — @vishwjeet-pawar03).
- Citation improvements: Chinese square-bracket citations handled ([#1005](https://github.com/pipeshub-ai/pipeshub-ai/pull/1005) — @abhishekgml1991), Excel citation highlighting fixed ([#1035](https://github.com/pipeshub-ai/pipeshub-ai/pull/1035)), and web-URL citation text matching added and then enhanced ([#1036](https://github.com/pipeshub-ai/pipeshub-ai/pull/1036), [#1039](https://github.com/pipeshub-ai/pipeshub-ai/pull/1039) — @vishwjeet-pawar03).
- Fixed answer regeneration ([#1047](https://github.com/pipeshub-ai/pipeshub-ai/pull/1047)), streaming ([#1007](https://github.com/pipeshub-ai/pipeshub-ai/pull/1007) — @kaushal1999), and metadata-enhancement bugs in search-result flattening and domain extraction ([#1019](https://github.com/pipeshub-ai/pipeshub-ai/pull/1019), [#972](https://github.com/pipeshub-ai/pipeshub-ai/pull/972)).
- The model name is shown with each response ([#1051](https://github.com/pipeshub-ai/pipeshub-ai/pull/1051) — @vishwjeet-pawar03), LLM health checks use a better test image and clearer messages ([#1011](https://github.com/pipeshub-ai/pipeshub-ai/pull/1011), [#1049](https://github.com/pipeshub-ai/pipeshub-ai/pull/1049) — @kaushal1999), and queries with no accessible records return a proper message ([#1050](https://github.com/pipeshub-ai/pipeshub-ai/pull/1050)).
