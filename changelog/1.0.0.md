# 1.0.0 — Code graphs, deeper retrieval and agent tools, and stricter permission enforcement

**Released:** October 27, 2026 · **Channel:** Stable · **Tag:** [`v1.0.0`](https://github.com/pipeshub-ai/pipeshub-ai/releases/tag/v1.0.0)

1.0.0 adds code graphs for indexed repositories, a reworked retrieval pipeline with focused reading and timeline search, custom API actions for agents, and stricter permission enforcement across connectors, chat and OAuth. It also brings a new Zendesk connector, staged indexing, and a long list of connector, parsing and reliability fixes.

Several changes need attention before you upgrade: SAML and generic OAuth sign-in are removed, `client_credentials` applications must name a service account, the Helm chart requires a Qdrant API key, and focused reading, timeline summaries and MCP servers are now on by default. See the upgrade notes first.

## Breaking changes & upgrade notes

- **Sign-in:** SAML and generic OAuth sign-in are removed. Review deployments that use these methods before upgrading ([#4217](https://github.com/pipeshub-ai/pipeshub-ai/pull/4217)).
- **Application identity:** applications that use `client_credentials` must name the service account they act as. Administrators can bind existing applications to a service account ([#4517](https://github.com/pipeshub-ai/pipeshub-ai/pull/4517), [#4538](https://github.com/pipeshub-ai/pipeshub-ai/pull/4538)).
- **Helm:** a Qdrant API key is required; the chart no longer supplies a default ([#3893](https://github.com/pipeshub-ai/pipeshub-ai/pull/3893)).
- **Connector API:** `POST /connectors/:connectorId/filters` is deprecated ([#4263](https://github.com/pipeshub-ai/pipeshub-ai/pull/4263)).
- **Defaults:** focused reading (`TARGETED_RETRIEVAL`), timeline summaries (`TIMELINE_SUMMARIES`) and MCP servers are enabled by default ([#4343](https://github.com/pipeshub-ai/pipeshub-ai/pull/4343), [#4349](https://github.com/pipeshub-ai/pipeshub-ai/pull/4349), [#4430](https://github.com/pipeshub-ai/pipeshub-ai/pull/4430)).
- **Experimental features stay opt-in:** knowledge-base push (`ENABLE_KB_PUSH`), PostgreSQL infrastructure backends and migration tooling. Artifact-set writes and reads are gated separately ([#4764](https://github.com/pipeshub-ai/pipeshub-ai/pull/4764), [#4704](https://github.com/pipeshub-ai/pipeshub-ai/pull/4704), [#4705](https://github.com/pipeshub-ai/pipeshub-ai/pull/4705), [#4706](https://github.com/pipeshub-ai/pipeshub-ai/pull/4706), [#4574](https://github.com/pipeshub-ai/pipeshub-ai/pull/4574), [#4599](https://github.com/pipeshub-ai/pipeshub-ai/pull/4599)).

## Defaults & new settings

| Setting | Change | Default |
|---|---|---|
| `TARGETED_RETRIEVAL` | Focused reading of the relevant part of a record is now enabled by default | on |
| `TIMELINE_SUMMARIES` | Timeline summaries are now enabled by default | on |
| MCP servers | Now enabled by default | on |
| `ENABLE_KB_PUSH` | Opt-in push of application/blocks records through the KB API | off |
| Qdrant API key (Helm) | Now required; the chart no longer supplies one | — |

## Highlights

### Code graph

Repositories can be indexed into a navigable graph, with agent tools for code exploration and impact analysis. Later work improved TypeScript call resolution, extended impact traversal to five levels and path searches to eight hops ([#3841](https://github.com/pipeshub-ai/pipeshub-ai/pull/3841), [#4809](https://github.com/pipeshub-ai/pipeshub-ai/pull/4809), [#4844](https://github.com/pipeshub-ai/pipeshub-ai/pull/4844), [#4926](https://github.com/pipeshub-ai/pipeshub-ai/pull/4926)).

### Unified context pipeline and focused retrieval

Context is relevance-ordered, with deeper fusion, record-level result cuts, better exact-text matching and improved handling of images, lists, tables and neighboring passages. Agents can read only the relevant portion of a record, search a date range period by period, and use timeline search automatically for spans longer than a month ([#3489](https://github.com/pipeshub-ai/pipeshub-ai/pull/3489), [#4143](https://github.com/pipeshub-ai/pipeshub-ai/pull/4143), [#4146](https://github.com/pipeshub-ai/pipeshub-ai/pull/4146), [#4254](https://github.com/pipeshub-ai/pipeshub-ai/pull/4254), [#4291](https://github.com/pipeshub-ai/pipeshub-ai/pull/4291), [#4296](https://github.com/pipeshub-ai/pipeshub-ai/pull/4296), [#4373](https://github.com/pipeshub-ai/pipeshub-ai/pull/4373), [#4386](https://github.com/pipeshub-ai/pipeshub-ai/pull/4386)).

### Custom API actions

An organization's REST APIs can be connected from an OpenAPI specification. Users can add personal actions and connect actions directly from chat ([#4435](https://github.com/pipeshub-ai/pipeshub-ai/pull/4435), [#4324](https://github.com/pipeshub-ai/pipeshub-ai/pull/4324), [#4227](https://github.com/pipeshub-ai/pipeshub-ai/pull/4227)).

### Permission enforcement

Jira issue-security levels are enforced, SharePoint/OneDrive sharing and inherited access are corrected, stored record access rules are preserved, and team grants no longer make knowledge-base members owners. Synchronization is also safer: interrupted full syncs resume, cleanup waits for sync completion, and existing access is kept when a permission read fails ([#4738](https://github.com/pipeshub-ai/pipeshub-ai/pull/4738), [#4350](https://github.com/pipeshub-ai/pipeshub-ai/pull/4350), [#4772](https://github.com/pipeshub-ai/pipeshub-ai/pull/4772), [#4767](https://github.com/pipeshub-ai/pipeshub-ai/pull/4767), [#4626](https://github.com/pipeshub-ai/pipeshub-ai/pull/4626), [#4081](https://github.com/pipeshub-ai/pipeshub-ai/pull/4081), [#4112](https://github.com/pipeshub-ai/pipeshub-ai/pull/4112), [#4119](https://github.com/pipeshub-ai/pipeshub-ai/pull/4119), [#4485](https://github.com/pipeshub-ai/pipeshub-ai/pull/4485), [#3732](https://github.com/pipeshub-ai/pipeshub-ai/pull/3732)).

### Staged indexing

Classification and entity extraction run as their own stages with an LLM gateway, per-stage retry and status reporting, connector fairness and better recovery of stranded work ([#3270](https://github.com/pipeshub-ai/pipeshub-ai/pull/3270), [#4467](https://github.com/pipeshub-ai/pipeshub-ai/pull/4467), [#4564](https://github.com/pipeshub-ai/pipeshub-ai/pull/4564), [#4194](https://github.com/pipeshub-ai/pipeshub-ai/pull/4194), [#4215](https://github.com/pipeshub-ai/pipeshub-ai/pull/4215)).

### Zendesk connector

Syncs tickets, Help Center content, users, groups and organizations ([#2836](https://github.com/pipeshub-ai/pipeshub-ai/pull/2836)).

- **Dependencies** — vulnerable Python, Node and frontend dependencies updated; python-jose replaced with PyJWT; CI blocks newly introduced high or critical vulnerable dependencies ([#4265](https://github.com/pipeshub-ai/pipeshub-ai/pull/4265), [#4669](https://github.com/pipeshub-ai/pipeshub-ai/pull/4669)).

## Performance & reliability

- **Indexing** — token-based OpenAI/Azure embedding batches, query priority over indexing in the bundled embedding server, lower per-turn CPU, cacheable enrichment prompts and faster steady-state startup ([#4197](https://github.com/pipeshub-ai/pipeshub-ai/pull/4197), [#4196](https://github.com/pipeshub-ai/pipeshub-ai/pull/4196), [#4290](https://github.com/pipeshub-ai/pipeshub-ai/pull/4290), [#4233](https://github.com/pipeshub-ai/pipeshub-ai/pull/4233), [#4298](https://github.com/pipeshub-ai/pipeshub-ai/pull/4298)).
- **Indexing** — prevent orphaned parser workers, release worker heaps, reduce Docling memory retention, bound image-heavy processing, make parse workers killable, and terminate repeatedly crashing records without charging queued work for those crashes ([#4666](https://github.com/pipeshub-ai/pipeshub-ai/pull/4666), [#4787](https://github.com/pipeshub-ai/pipeshub-ai/pull/4787), [#4800](https://github.com/pipeshub-ai/pipeshub-ai/pull/4800), [#4874](https://github.com/pipeshub-ai/pipeshub-ai/pull/4874), [#4832](https://github.com/pipeshub-ai/pipeshub-ai/pull/4832), [#4928](https://github.com/pipeshub-ai/pipeshub-ai/pull/4928)).
