# 0.9.1 — OAuth and PKCE hardening, a path-traversal fix, and a Kafka consumer that stops losing messages

**Released:** September 28, 2026 · **Channel:** Stable · **Tag:** [`v0.9.1`](https://github.com/pipeshub-ai/pipeshub-ai/releases/tag/v0.9.1)

0.9.1 is a patch release on top of [0.9.0](0.9.0.md), published the same day with 20 merged PRs. Most of it is security work: OAuth app management and consent now require a real sign-in session, PKCE is enforced where authorization codes are issued and redeemed, and a path-traversal hole in the record convert API is closed. It also fixes a Kafka consumer that could skip messages after a temporary failure, and permission-checks the related records that graph enrichment adds to a chat prompt. **Upgrade from 0.9.0 is recommended.**

The 1.7.0 TypeScript, Python and Go SDKs were generated from the 0.9.1 API spec; their changes are described in the [0.9.0 changelog](0.9.0.md#sdks--170-typescript-python-go).

## Highlights

### OAuth apps, personal access tokens and consent require a sign-in session

OAuth app management and the consent endpoints accepted OAuth access tokens and personal access tokens. A token with any scope could create an app with broader scopes, read or regenerate client secrets, or approve a consent request for itself. Every `/oauth-clients/*` and `/personal-access-tokens/*` route and the consent `POST /oauth2/authorize` now require the user's interactive session JWT, and answer `403` to OAuth access tokens and PATs. PAT scopes are capped at the instance's `MCP_SCOPES` ([#3626](https://github.com/pipeshub-ai/pipeshub-ai/pull/3626) — @rish664).

### PKCE enforced where the code is issued and redeemed

PKCE was checked only on `GET /oauth2/authorize`, which returns consent data, not the code. A caller that skipped the GET could get a public-client code without a challenge and redeem it with no verifier and no client secret, and the `plain` method let a caller send its own challenge back as the verifier. A public client now must send a `code_challenge` to the consent `POST`, only `S256` is accepted, and discovery advertises only `S256` ([#3630](https://github.com/pipeshub-ai/pipeshub-ai/pull/3630) — @rish231294).

### Record convert API: no more writes outside the temp folder

`POST /api/v1/record/buffer/convert` built its temp file path from the unsanitized upload filename, so an absolute path or `../` in the name let any signed-in user write a file anywhere the connectors service could write. The filename is no longer trusted for the path ([#3628](https://github.com/pipeshub-ai/pipeshub-ai/pull/3628) — @rish231294).

## Breaking changes & upgrade notes

- **OAuth app, personal access token and consent routes reject OAuth access tokens and PATs with `403`.** Scripts that manage OAuth apps or mint PATs with a token must use a user's sign-in session instead ([#3626](https://github.com/pipeshub-ai/pipeshub-ai/pull/3626)).
- **PKCE `plain` is rejected with `400`.** Public clients must send an `S256` `code_challenge` on both the authorize `GET` and the consent `POST`; without it the consent redirects with `error=invalid_request` and no code. Confidential clients may still omit PKCE ([#3630](https://github.com/pipeshub-ai/pipeshub-ai/pull/3630)).
- **The service-account email domain is reserved.** A person can no longer be given an address in `service.pipeshub.internal`, through invites, user creation or an email change ([#3612](https://github.com/pipeshub-ai/pipeshub-ai/pull/3612)).

## Agents & AI

- **Graph enrichment respects permissions.** The parents, children and attachments that enrichment adds to search results (Jira, Confluence, Linear) are now permission-checked in one batch, and their number is capped, so names, URLs and summaries of records a user cannot open no longer reach the prompt. A new `filter_accessible_record_ids` provider method backs it on Neo4j and ArangoDB ([#3590](https://github.com/pipeshub-ai/pipeshub-ai/pull/3590) — @darshangodase).
- **Agent tools** — behaviour tests for the GitHub, Jira and ClickUp tools, and fixes for the bugs they found ([#3582](https://github.com/pipeshub-ai/pipeshub-ai/pull/3582)); the agent answers from the workspace's data when the Acme Corp demo is its only knowledge ([#3609](https://github.com/pipeshub-ai/pipeshub-ai/pull/3609)) — @shekharkadyan.

## Fixes

- **Kafka** — the Kafka consumer used by the connectors and query services no longer loses messages after a temporary handler failure. The indexing consumer was not affected ([#3515](https://github.com/pipeshub-ai/pipeshub-ai/pull/3515)).
- **Google** — the personal Drive and Gmail connectors keep the fresher OAuth token after the library refreshes it, and save refreshed tokens to settings, which ends a refresh loop ([#3571](https://github.com/pipeshub-ai/pipeshub-ai/pull/3571)).
- **Web** — stored ETag and Last-Modified values are read from the file record ([#3622](https://github.com/pipeshub-ai/pipeshub-ai/pull/3622)).
- **Frontend** — three wordings the locale pass changed are restored ([#3610](https://github.com/pipeshub-ai/pipeshub-ai/pull/3610)).

All by @shekharkadyan.

## Security & authentication

- **Service accounts** — a person can no longer be given an address in the reserved service-account domain, on any of the four paths that set an email, and the service-account routes get the same rate limit as the token and OAuth app routes ([#3612](https://github.com/pipeshub-ai/pipeshub-ai/pull/3612) — @shekharkadyan).
- **Toolset OAuth callback** — a failed agent access check is answered with JSON instead of a redirect to a caller-supplied address, which the Node API used to follow on the server ([#3611](https://github.com/pipeshub-ai/pipeshub-ai/pull/3611) — @shekharkadyan).
- **S3** — the bucket name and region are matched literally when a stored file URL is read back, so a bucket such as `my.bucket` no longer also matches `myxbucket` ([#3608](https://github.com/pipeshub-ai/pipeshub-ai/pull/3608) — @shekharkadyan).

## Developer experience & infrastructure

- **AWS EKS** — S3 on EKS gets a SigV4 preload config map in the Helm chart, EKS values and docs updates, and a bucket purge test ([#3634](https://github.com/pipeshub-ai/pipeshub-ai/pull/3634) — @abhishekgml1991).
- **Tests and CI** — a weekly sustained-load test for search and chat that fails on errors and p95 regressions ([#3614](https://github.com/pipeshub-ai/pipeshub-ai/pull/3614)); a frontend unit-test coverage minimum ([#3577](https://github.com/pipeshub-ai/pipeshub-ai/pull/3577)); the shared "test" logger is no longer silenced for later tests ([#3613](https://github.com/pipeshub-ai/pipeshub-ai/pull/3613)); storage tokens are minted for the user the test client acts as ([#3623](https://github.com/pipeshub-ai/pipeshub-ai/pull/3623)); chat stream mocks really end or stay open ([#3624](https://github.com/pipeshub-ai/pipeshub-ai/pull/3624)); a missing SMB folder reads as an empty listing in the integration tests ([#3620](https://github.com/pipeshub-ai/pipeshub-ai/pull/3620)) — all @shekharkadyan.
