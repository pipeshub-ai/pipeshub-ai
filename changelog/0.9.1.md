# 0.9.1 — OAuth and PKCE hardening, a path-traversal fix, a Kafka consumer that stops losing messages, and SDK 1.7.0

**Released:** September 28, 2026 · **Channel:** Stable · **Tag:** [`v0.9.1`](https://github.com/pipeshub-ai/pipeshub-ai/releases/tag/v0.9.1)

0.9.1 is a patch release on top of [0.9.0](0.9.0.md), published the same day with 20 merged PRs. Most of it is security work: OAuth app management and consent now require a real sign-in session, PKCE is enforced where authorization codes are issued and redeemed, and a path-traversal hole in the record convert API is closed. It also fixes a Kafka consumer that could skip messages after a temporary failure, and permission-checks the related records that graph enrichment adds to a chat prompt. **Upgrade from 0.9.0 is recommended.**

The **1.7.0 SDKs** for TypeScript, Python and Go, released on October 12, 2026, are compatible with 0.9.1. They contain breaking changes; the fix for each one, in each language, is in the [SDK section](#sdks--170-typescript-python-go) below.

## Breaking changes & upgrade notes

- **OAuth app, personal access token, consent and device-flow routes reject OAuth access tokens and PATs with `403`.** This covers `/oauth-clients/*`, `/personal-access-tokens/*`, `POST /oauth2/authorize`, `/device/verify` and `/device/consent`. Scripts that manage OAuth apps, mint PATs or approve a device login with a token must use a user's sign-in session instead ([#3626](https://github.com/pipeshub-ai/pipeshub-ai/pull/3626)).
- **PKCE `plain` is rejected with `400`.** Public clients must send an `S256` `code_challenge` on both the authorize `GET` and the consent `POST`; without it the consent redirects with `error=invalid_request` and no code. Confidential clients may still omit PKCE ([#3630](https://github.com/pipeshub-ai/pipeshub-ai/pull/3630)).
- **The service-account email domain is reserved.** A person can no longer be given an address in `service.pipeshub.internal`, through invites, user creation or an email change ([#3612](https://github.com/pipeshub-ai/pipeshub-ai/pull/3612)).
- **SDK users:** the 1.7.0 SDKs contain breaking changes. See the next section.

## Highlights

### OAuth apps, personal access tokens and consent require a sign-in session

OAuth app management and the consent endpoints accepted OAuth access tokens and personal access tokens. A token with any scope could create an app with broader scopes, read or regenerate client secrets, or approve a consent request for itself. Every `/oauth-clients/*` and `/personal-access-tokens/*` route, the consent `POST /oauth2/authorize`, and the device-flow `/device/verify` and `/device/consent` routes now require the user's interactive session JWT, and answer `403` to OAuth access tokens and PATs. PAT scopes are capped at the instance's `MCP_SCOPES` ([#3626](https://github.com/pipeshub-ai/pipeshub-ai/pull/3626) — @rish664).

### PKCE enforced where the code is issued and redeemed

PKCE was checked only on `GET /oauth2/authorize`, which returns consent data, not the code. A caller that skipped the GET could get a public-client code without a challenge and redeem it with no verifier and no client secret, and the `plain` method let a caller send its own challenge back as the verifier. A public client now must send a `code_challenge` to the consent `POST`, only `S256` is accepted, and discovery advertises only `S256` ([#3630](https://github.com/pipeshub-ai/pipeshub-ai/pull/3630) — @rish231294).

### Record convert API: no more writes outside the temp folder

`POST /api/v1/record/buffer/convert` built its temp file path from the unsanitized upload filename, so an absolute path or `../` in the name let any signed-in user write a file anywhere the connectors service could write. The filename is no longer trusted for the path ([#3628](https://github.com/pipeshub-ai/pipeshub-ai/pull/3628) — @rish231294).

## SDKs — 1.7.0 (TypeScript, Python, Go)

The TypeScript, Python and Go SDKs move from 1.6.0 to **1.7.0**, released on October 12, 2026, and are compatible with PipesHub 0.9.1: [`@pipeshub-ai/sdk`](https://github.com/pipeshub-ai/pipeshub-sdk-typescript) ([v1.7.0 release](https://github.com/pipeshub-ai/pipeshub-sdk-typescript/releases/tag/v1.7.0)), [`pipeshub-sdk`](https://github.com/pipeshub-ai/pipeshub-sdk-python) ([v1.7.0 release](https://github.com/pipeshub-ai/pipeshub-sdk-python/releases/tag/v1.7.0)) and [`pipeshub-sdk-go`](https://github.com/pipeshub-ai/pipeshub-sdk-go) ([v1.7.0 release](https://github.com/pipeshub-ai/pipeshub-sdk-go/releases/tag/v1.7.0)), all by @rish664.

> **1.7.0 is a minor version, but it contains breaking changes.** Read the list for your language before you upgrade.

### TypeScript

#### Renaming a conversation no longer returns `messages`

`updateConversationTitle` returns only the updated conversation fields. Read the messages with a second call.

```ts
// ❌ 1.6.0
// const res = await sdk.conversations.updateConversationTitle({ conversationId, body: { title } });
// const messages = res.conversation.messages;

// ✅ 1.7.0
await sdk.conversations.updateConversationTitle({ conversationId, body: { title } });
const { conversation } = await sdk.conversations.getConversationById({ conversationId });
const messages = conversation?.messages ?? [];
```

#### Deleting an agent conversation: `conversation` can be empty

`conversation` is now a stored conversation, an empty object, or `null`. Check it before you read a field.

```ts
const res = await sdk.agents.deleteAgentConversationById({ agentKey, conversationId });

// ❌ 1.6.0
// console.log(res.conversation.id);

// ✅ 1.7.0
if (res.conversation && "id" in res.conversation) {
  console.log(res.conversation.id);
}
```

#### Some type names changed

Use the new name. The data inside is the same.

| Old name | New name | Import from |
|---|---|---|
| `Meta` | `MessageFeedbackUpdateResponseMeta` | `@pipeshub-ai/sdk/models` |
| `ModelInfo` | `ConversationListItemModelInfo` | `@pipeshub-ai/sdk/models` |
| `IsArchived` | `ListAgentConversationsIsArchived` | `@pipeshub-ai/sdk/models/operations` |
| `GetConversationByIdMessage` | `Message` | `@pipeshub-ai/sdk/models/operations` |
| `GetConversationByIdMessageMessageType` | `MessageMessageType` | `@pipeshub-ai/sdk/models/operations` |
| `GetConversationByIdContentFormat` | `ContentFormat` | `@pipeshub-ai/sdk/models/operations` |
| `GetConversationByIdReferenceDatum` | `ReferenceDatum` | `@pipeshub-ai/sdk/models/operations` |
| `GetConversationByIdAppliedFilters` | `AppliedFilters` | `@pipeshub-ai/sdk/models/operations` |

The `UpdateConversationTitle*` message types are removed, because renaming a conversation no longer returns messages.

```ts
// ❌ 1.6.0
// import { Meta, ModelInfo } from "@pipeshub-ai/sdk/models";
// import { IsArchived, GetConversationByIdMessage } from "@pipeshub-ai/sdk/models/operations";

// ✅ 1.7.0

```

#### Two errors have a new error class

A `500` from `knowledgeBase.uploadRecords` is now thrown as `ErrorResponse`. A `410` from `userAccount.authenticate` is no longer an `ErrorResponse`. Both classes extend `PipeshubError`, so catch the parent class and check the status code.

```ts
import * as errors from "@pipeshub-ai/sdk/models/errors";

try {
  await sdk.knowledgeBase.uploadRecords(request);
} catch (e) {
  if (e instanceof errors.PipeshubError && e.statusCode === 500) {
    // handle the server error
  } else {
    throw e;
  }
}
```

#### Behavior notes (not breaking)

- **A user token on 22 endpoints.** OAuth apps, personal access tokens, user info, org auth config and reset password now send only the user token. If you set up only an app token, add a user token:
  ```ts
  const sdk = new Pipeshub({ security: { bearerAuth: userToken } });
  ```
- **Stream event `data` stays a string.** Code that calls `JSON.parse(event.data)` keeps working.

### Python

#### Renaming a conversation no longer returns `messages`

`update_conversation_title` returns only the updated conversation fields. Read the messages with a second call.

```python
# ❌ 1.6.0
# res = sdk.conversations.update_conversation_title(conversation_id=cid, title=title)

messages = (res.conversation.messages or []) if res.conversation else []
```

#### Deleting an agent conversation: `conversation` can be empty

`conversation` is now a stored conversation, an empty object, or `None`. Your code runs as before, but type checkers need a check before you read a field.

```python
from pipeshub_sdk import models

res = sdk.agents.delete_agent_conversation_by_id(agent_key=agent_key, conversation_id=cid)
c = res.conversation
if isinstance(c, models.StoredAgentConversation):
    print(c.id)
```

#### Two errors have a new error class

A `500` from `knowledge_base.upload_records` is now raised as `ErrorResponse`. A `410` from `user_account.authenticate` is now `PipeshubDefaultError`, not `ErrorResponse`. Both classes extend `PipeshubError`, so catch the parent class and check the status code.

```python
from pipeshub_sdk import errors

try:
    sdk.knowledge_base.upload_records(...)
except errors.PipeshubError as e:
    if e.status_code == 500:
        ...  # handle the server error
```

#### A citation can have two shapes

A message citation is now a `CitationReference` or a `PopulatedCitationReference`. Your code runs as before, but type checkers need a check before you read a field.

```python
from pipeshub_sdk import models

for c in msg.citations or []:
    if isinstance(c, models.CitationReference):
        print(c.citation_id)
```

#### Behavior notes (not breaking)

- **A user token on 22 endpoints.** OAuth apps, personal access tokens, user info, org auth config and reset password now send only the user token. If you set up only an app token, add a user token:
  ```python
  sdk = Pipeshub(security=models.Security(bearer_auth=user_token))
  ```
- **Conversation streams work.** `data` on `ConversationStreamSSEEvent` and `ConversationMessageStreamSSEEvent` is typed `Any`, as on the other stream models. The SDK decodes each event's JSON before validation, so the old `str` type rejected those events.

#### Two errors have a new error type

A `500` from `KnowledgeBase.UploadRecords` is now returned as `*apierrors.ErrorResponse`. A `410` from `UserAccount.Authenticate` is now the default `*apierrors.APIError`, not `*apierrors.ErrorResponse`. Check for both types.

```go
var errResp *apierrors.ErrorResponse
var apiErr *apierrors.APIError
switch {
case errors.As(err, &errResp):
	// error with a JSON body
case errors.As(err, &apiErr) && apiErr.StatusCode == 410:
	// the 410 from Authenticate
}
```

#### `Success` is always `true`

On the delete-record, reindex-record, reindex-record-group and knowledge-hub-nodes responses, `Success` is no longer a public field. A `200` already means success, so you can drop the check, or use the getter.

```go
// ❌ 1.6.0
// if res.DeleteRecordResponseSchema.Success { ... }

// ✅ 1.7.0
if res.DeleteRecordResponseSchema.GetSuccess() { ... }
```

#### A citation can have two shapes

A message citation is now a `components.CitationUnion`: a `CitationReference` or a `PopulatedCitationReference`. Read the citation through its wrapper.

```go
// ❌ 1.6.0
// for _, c := range msg.Citations { fmt.Println(*c.CitationID) }

// ✅ 1.7.0
for _, c := range msg.Citations {

		fmt.Println(*c.CitationReference.CitationID)

```

## Bug fixes

- **Storage & data layer** — the Kafka consumer used by the connectors and query services no longer loses messages after a temporary handler failure. The indexing consumer was not affected ([#3515](https://github.com/pipeshub-ai/pipeshub-ai/pull/3515) — @shekharkadyan).
- **Google Drive & Gmail connectors** — the personal Drive and Gmail connectors keep the fresher OAuth token after the library refreshes it, and save refreshed tokens to settings, which ends a refresh loop ([#3571](https://github.com/pipeshub-ai/pipeshub-ai/pull/3571) — @shekharkadyan).
- **Web connector** — stored ETag and Last-Modified values are read from the file record ([#3622](https://github.com/pipeshub-ai/pipeshub-ai/pull/3622) — @shekharkadyan).
- **Agents** — behaviour tests for the GitHub, Jira and ClickUp tools, and fixes for the bugs they found ([#3582](https://github.com/pipeshub-ai/pipeshub-ai/pull/3582)); the agent answers from the workspace's data when the Acme Corp demo is its only knowledge ([#3609](https://github.com/pipeshub-ai/pipeshub-ai/pull/3609)) — @shekharkadyan.
- **UI** — three wordings the locale pass changed are restored ([#3610](https://github.com/pipeshub-ai/pipeshub-ai/pull/3610) — @shekharkadyan).

## Security fixes

- **Auth** — OAuth app, personal access token and consent routes now require the user's interactive session JWT and answer `403` to OAuth access tokens and PATs, and PAT scopes are capped at `MCP_SCOPES` ([#3626](https://github.com/pipeshub-ai/pipeshub-ai/pull/3626) — @rish664). See [the highlight](#oauth-apps-personal-access-tokens-and-consent-require-a-sign-in-session).
- **Auth** — PKCE is enforced on the consent `POST` where the code is issued, public clients must send a `code_challenge`, and only `S256` is accepted ([#3630](https://github.com/pipeshub-ai/pipeshub-ai/pull/3630) — @rish231294). See [the highlight](#pkce-enforced-where-the-code-is-issued-and-redeemed).
- **API** — `POST /api/v1/record/buffer/convert` no longer builds its temp file path from the unsanitized upload filename, so a crafted name can no longer write outside the temp folder ([#3628](https://github.com/pipeshub-ai/pipeshub-ai/pull/3628) — @rish231294). See [the highlight](#record-convert-api-no-more-writes-outside-the-temp-folder).
- **Search & chat** — graph enrichment respects permissions. The parents, children and attachments that enrichment adds to search results (Jira, Confluence, Linear) are now permission-checked in one batch, and their number is capped, so names, URLs and summaries of records a user cannot open no longer reach the prompt. A new `filter_accessible_record_ids` provider method backs it on Neo4j and ArangoDB ([#3590](https://github.com/pipeshub-ai/pipeshub-ai/pull/3590) — @darshangodase).
- **Auth** — service accounts: a person can no longer be given an address in the reserved service-account domain, on any of the four paths that set an email, and the service-account routes get the same rate limit as the token and OAuth app routes ([#3612](https://github.com/pipeshub-ai/pipeshub-ai/pull/3612) — @shekharkadyan).
- **Auth** — toolset OAuth callback: a failed agent access check is answered with JSON instead of a redirect to a caller-supplied address, which the Node API used to follow on the server ([#3611](https://github.com/pipeshub-ai/pipeshub-ai/pull/3611) — @shekharkadyan).
- **Storage & data layer** — S3: the bucket name and region are matched literally when a stored file URL is read back, so a bucket such as `my.bucket` no longer also matches `myxbucket` ([#3608](https://github.com/pipeshub-ai/pipeshub-ai/pull/3608) — @shekharkadyan).

## Developer experience & infrastructure

- **Deployment** — S3 on AWS EKS gets a SigV4 preload config map in the Helm chart, EKS values and docs updates, and a bucket purge test ([#3634](https://github.com/pipeshub-ai/pipeshub-ai/pull/3634) — @abhishekgml1991).
- **Tests** — a weekly sustained-load test for search and chat that fails on errors and p95 regressions ([#3614](https://github.com/pipeshub-ai/pipeshub-ai/pull/3614)); a frontend unit-test coverage minimum ([#3577](https://github.com/pipeshub-ai/pipeshub-ai/pull/3577)); the shared "test" logger is no longer silenced for later tests ([#3613](https://github.com/pipeshub-ai/pipeshub-ai/pull/3613)); storage tokens are minted for the user the test client acts as ([#3623](https://github.com/pipeshub-ai/pipeshub-ai/pull/3623)); chat stream mocks really end or stay open ([#3624](https://github.com/pipeshub-ai/pipeshub-ai/pull/3624)); a missing SMB folder reads as an empty listing in the integration tests ([#3620](https://github.com/pipeshub-ai/pipeshub-ai/pull/3620)) — all @shekharkadyan.
