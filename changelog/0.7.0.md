# 0.7.0 — Personal access tokens, a GitHub connector, AWS Bedrock, and a one-command installer

**Released:** August 26, 2026 · **Channel:** Stable · **Tag:** [`v0.7.0`](https://github.com/pipeshub-ai/pipeshub-ai/releases/tag/v0.7.0)

0.7.0 opens PipesHub up to external tooling and new deployment shapes. Any member can now mint a scoped, revocable personal access token to connect an external agent or script to the API and MCP server, and the MCP server itself runs on the new agent loop. A GitHub teams connector and a HackerNews datasource join the connector catalog, a code parser makes source files searchable with correct citations, and multimodal embeddings, an EPUB parser, and AWS Bedrock widen the model and content layer. Self-hosting gets a one-command Docker installer that pulls fresh images, checks host resources, and reports clearly when something fails on first run. Roughly 100 merged PRs since 0.6.0.

Operators should read the upgrade notes: org admin privilege moves from admin user groups to a `role` field on users via a boot migration, a storage-record org-ID backfill runs on startup, the installer renames Compose containers, and MCP / Actions are now controlled from Labs feature flags rather than environment variables.

## Highlights

### Personal access tokens for MCP and API access

Any org member can create a long-lived, scoped, revocable Personal Access Token under Workspace → Developer Settings, for example to connect an external agent to the PipesHub MCP server without borrowing a 24-hour session token or an admin-owned OAuth app that ignores per-user permissions. PATs are minted through the existing OAuth access-token machinery via an auto-created per-org system app, carry a `phpat_` prefix so secret scanners recognize them, and default to a 30-day expiry ([#2933](https://github.com/pipeshub-ai/pipeshub-ai/pull/2933) — @shekharkadyan). They are documented in the OpenAPI spec ([#2940](https://github.com/pipeshub-ai/pipeshub-ai/pull/2940)), and a follow-up fixed PATs failing on any route that forwards the auth header to a downstream service ([#2971](https://github.com/pipeshub-ai/pipeshub-ai/pull/2971)).

### MCP server on the new agent loop, gated from Labs

The MCP server now runs its tools through the new agent loop ([#2830](https://github.com/pipeshub-ai/pipeshub-ai/pull/2830) — @tushar1245). MCP is enabled from the Labs settings page rather than an environment variable, and code execution is now env-only via `PIPESHUB_ENABLE_CODE_EXECUTION` ([#3044](https://github.com/pipeshub-ai/pipeshub-ai/pull/3044)). Actions and toolsets sit behind a new `ENABLE_ACTIONS` platform flag, enabled by default, so admins can hide them from the navigation, agent builder, and chat ([#3045](https://github.com/pipeshub-ai/pipeshub-ai/pull/3045)). A schema-loss bug that broke MCP tool arguments was fixed ([#3078](https://github.com/pipeshub-ai/pipeshub-ai/pull/3078)).

### GitHub teams connector, HackerNews datasource, and a code parser

A GitHub teams connector lands, with the personal GitHub connector refactored to share its methods ([#2989](https://github.com/pipeshub-ai/pipeshub-ai/pull/2989) — @darshangodase). A HackerNews API client and datasource were contributed ([#3060](https://github.com/pipeshub-ai/pipeshub-ai/pull/3060) — @igennova). Source files are now parsed by a dedicated code parser ([#3014](https://github.com/pipeshub-ai/pipeshub-ai/pull/3014) — @jatingaur18) and citations into code files were fixed ([#3064](https://github.com/pipeshub-ai/pipeshub-ai/pull/3064)).

### Multimodal embeddings, EPUB, AWS Bedrock, and pasted text

Multimodal embeddings and an EPUB parser were added ([#2919](https://github.com/pipeshub-ai/pipeshub-ai/pull/2919) — @abhishekgml1991), with support for multimodal OpenAI-compatible embedding endpoints ([#2952](https://github.com/pipeshub-ai/pipeshub-ai/pull/2952) — @TatshSiow) and image context-engineering changes so images reach the model with better surrounding context ([#3084](https://github.com/pipeshub-ai/pipeshub-ai/pull/3084)). AWS Bedrock joins the supported model providers ([#3062](https://github.com/pipeshub-ai/pipeshub-ai/pull/3062) — @abhishekgml1991). In chat, long pasted text becomes an attachment chip with a preview dialog instead of flooding the input ([#2889](https://github.com/pipeshub-ai/pipeshub-ai/pull/2889)). Model access on an agent is now optional ([#2960](https://github.com/pipeshub-ai/pipeshub-ai/pull/2960)).

### Query service throughput, phase two

Building on the 0.6.0 overhaul, this round targets CPU in the query path: a read-through Redis cache of each user's accessible record IDs, invalidated from the connector and indexing services; batched graph and storage lookups with a bounded process-wide HTTP session and Redis client; optional direct provider-SDK transports for Azure OpenAI, OpenAI, Anthropic, and Gemini behind `PIPESHUB_AGENT_TRANSPORT`; and a fix for the Node gateway building a public key on every JWT verify ([#2963](https://github.com/pipeshub-ai/pipeshub-ai/pull/2963) — @shrikantNemiwal1). Measured at 4 workers / 32 users: steady-state throughput up from 37.8 to 43.0 req/min, p50 turn latency 34.4 s → 27.9 s, and Node gateway p50 2,738 ms → 573 ms. The accessible-records cache is on by default and can be disabled with `PIPESHUB_ACCESSIBLE_RECORDS_CACHE=0`; a loadtest harness ships alongside.

### Admin role moves to the user record

Org admin privilege now lives on `User.role` (`admin` | `member`) instead of membership in a legacy admin user group. A one-time boot migration promotes admin-group members, defaults everyone else to member, and soft-deletes the admin groups only if at least one admin remains. Access tokens carry the role, role changes force a logout, and last-admin demotion is blocked ([#2939](https://github.com/pipeshub-ai/pipeshub-ai/pull/2939) — @Pranjal-wq, integration tests in [#2981](https://github.com/pipeshub-ai/pipeshub-ai/pull/2981)). Follow-ups let members invite other members ([#3023](https://github.com/pipeshub-ai/pipeshub-ai/pull/3023)), confirm role changes and show Groups as an Enterprise placeholder ([#3005](https://github.com/pipeshub-ai/pipeshub-ai/pull/3005)), and allow changing the role on a pending invite ([#3056](https://github.com/pipeshub-ai/pipeshub-ai/pull/3056)).

### One-command Docker installer

A new `install.sh` at the repo root installs PipesHub with a single `curl | bash` or `./install.sh` from a clone. It checks Docker, RAM, and disk, offers slim vs full and a choice of graph database, broker, and KV store, writes a `.env` with random secrets, pulls fresh app and sandbox images, and waits until the app is reachable on the host. First-run failures are clearer: crash-loop detection distinguishes exit 137 from 139, a stale `COMPOSE_PROFILES` is repaired, and indexing model loaders try the local cache first so air-gapped hosts don't hang ([#2634](https://github.com/pipeshub-ai/pipeshub-ai/pull/2634) — @shekharkadyan). The installer now tells you where to re-run it after a curl or clone ([#3083](https://github.com/pipeshub-ai/pipeshub-ai/pull/3083)), and CI tests a first-run install against Docker Hub images ([#3076](https://github.com/pipeshub-ai/pipeshub-ai/pull/3076)).

### Stateless Docling processing and adaptive parsing

Docling document processing was separated into stateless services, with batched PDF processing for large documents and lightweight table enrichment when advanced enrichment is unavailable; legacy PDF-processing and block-creation endpoints were removed ([#2950](https://github.com/pipeshub-ai/pipeshub-ai/pull/2950) — @kaushal1999). An adaptive parsing strategy picks the parse path per document ([#2980](https://github.com/pipeshub-ai/pipeshub-ai/pull/2980) — @kaushalwaghela-art), vector-graphics-heavy PDFs no longer stall pdfplumber ([#3007](https://github.com/pipeshub-ai/pipeshub-ai/pull/3007)), and image-heavy PDF pages are routed to OCR ([#3033](https://github.com/pipeshub-ai/pipeshub-ai/pull/3033) — @TatshSiow).

## Breaking changes & upgrade notes

- **Admin role migration.** On first boot, admin user-group members are promoted to `role=admin` and the admin groups are soft-deleted; user JWTs without a valid role are rejected, so users re-login once. Admin checks now read the role from the database ([#2939](https://github.com/pipeshub-ai/pipeshub-ai/pull/2939)).
- **Org-ID backfill for storage records.** A startup migration backfills `orgId` on storage documents in MongoDB ([#3059](https://github.com/pipeshub-ai/pipeshub-ai/pull/3059) — @vishwjeet-pawar03).
- **Compose container names change.** Existing Docker Compose installs recreate every container on the next `./install.sh`; names become `{project}-{service}-1` (default `pipeshub-ai-pipeshub-ai-1`), so `docker exec pipeshub-ai` must become `docker compose -p pipeshub-ai exec -T pipeshub-ai …`. Data volumes are unchanged ([#2634](https://github.com/pipeshub-ai/pipeshub-ai/pull/2634)).
- **Feature flags move.** `ENABLE_MCP` is now controlled only from Labs (the `PIPESHUB_ENABLE_MCP` env override is gone); code execution is env-only via `PIPESHUB_ENABLE_CODE_EXECUTION` and its Labs toggle was removed ([#3044](https://github.com/pipeshub-ai/pipeshub-ai/pull/3044)). Actions/toolsets are gated by a new `ENABLE_ACTIONS` platform flag, default on ([#3045](https://github.com/pipeshub-ai/pipeshub-ai/pull/3045)).
- **New query-path defaults.** The accessible-records cache is enabled by default (`PIPESHUB_ACCESSIBLE_RECORDS_CACHE`); direct LLM transports (`PIPESHUB_AGENT_TRANSPORT=direct`) and signed-URL caching (`PIPESHUB_SIGNED_URL_CACHE_SECONDS`) are opt-in ([#2963](https://github.com/pipeshub-ai/pipeshub-ai/pull/2963)).
- **Docling API surface.** Legacy PDF-processing and block-creation endpoints were removed from the Docling service ([#2950](https://github.com/pipeshub-ai/pipeshub-ai/pull/2950)).
- **Embedding cleanups** are now behind a feature flag ([#3077](https://github.com/pipeshub-ai/pipeshub-ai/pull/3077) — @vishwjeet-pawar03).
