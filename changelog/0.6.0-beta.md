# 0.6.0-beta — New agent loop, standalone parsing & extraction services, OpenSearch arrives

**Released:** August 1, 2026 · **Channel:** Beta · **Tag:** [`v0.6.0-beta`](https://github.com/pipeshub-ai/pipeshub-ai/releases/tag/v0.6.0-beta)

*This beta was finalized as [0.6.0](0.6.0.md).*

This beta reworks two core engines: the agent runtime gets a new loop implementation, and document parsing and data extraction split out of indexing into their own services with concurrency, memory, and latency fixes to match. OpenSearch joins the supported search backends, web crawling moves to crawl4ai, and admins can bulk-invite users from CSV/Excel. Roughly 140 merged PRs since 0.5.0.

Operators upgrading should read the notes below: this release includes a knowledge-base record-group migration, a new parsing-service flag, and a raised Docker RAM limit.

## Highlights

### New agent loop

The agent runtime was reimplemented with a new loop ([#2702](https://github.com/pipeshub-ai/pipeshub-ai/pull/2702) — @abhishekgml1991), the release's largest change to how agents plan and execute. Alongside it, stale tasks in deep agents were fixed ([#2656](https://github.com/pipeshub-ai/pipeshub-ai/pull/2656) — @vishwjeet-pawar03) and reasoning-effort handling was updated for models that support it ([#2858](https://github.com/pipeshub-ai/pipeshub-ai/pull/2858)).

### Parsing and data extraction become standalone services

Document parsing and data extraction were separated out of the indexing path into their own services ([#2541](https://github.com/pipeshub-ai/pipeshub-ai/pull/2541) — @abhishekgml1991), gated by a parsing-service flag ([#2734](https://github.com/pipeshub-ai/pipeshub-ai/pull/2734)). Follow-ups hardened concurrency ([#2738](https://github.com/pipeshub-ai/pipeshub-ai/pull/2738)), fixed the HTML parser and other parsing paths ([#2749](https://github.com/pipeshub-ai/pipeshub-ai/pull/2749), [#2770](https://github.com/pipeshub-ai/pipeshub-ai/pull/2770) — @jatingaur18), added health status for both services ([#2845](https://github.com/pipeshub-ai/pipeshub-ai/pull/2845) — @rish664) plus build targets ([#2822](https://github.com/pipeshub-ai/pipeshub-ai/pull/2822)), and dropped base64 encoding when sending PDFs to the Docling service ([#2792](https://github.com/pipeshub-ai/pipeshub-ai/pull/2792) — @kaushal1999).

### Smarter, cheaper PDF and OCR pipeline

Docling is now the default PDF parser (with a BlockParser bug fix) and falls back to OCR when it fails ([#2724](https://github.com/pipeshub-ai/pipeshub-ai/pull/2724), [#2672](https://github.com/pipeshub-ai/pipeshub-ai/pull/2672) — @kaushal1999). OCR itself got safer and faster: an individual VLM-OCR instance per parse call ([#2739](https://github.com/pipeshub-ai/pipeshub-ai/pull/2739)), a cap on OCR-detection pages ([#2790](https://github.com/pipeshub-ai/pipeshub-ai/pull/2790)), and Docling memory and latency optimizations ([#2809](https://github.com/pipeshub-ai/pipeshub-ai/pull/2809)). Table indexing now batches its LLM calls ([#2844](https://github.com/pipeshub-ai/pipeshub-ai/pull/2844)).

### OpenSearch integration

OpenSearch is now a supported backend ([#2547](https://github.com/pipeshub-ai/pipeshub-ai/pull/2547) — @abhishekgml1991), extending the deployment options beyond the existing Qdrant/ArangoDB stack for organizations standardized on OpenSearch.

### Web connector rebuilt on crawl4ai

Web connectors gained crawl4ai support for higher-fidelity crawling ([#2641](https://github.com/pipeshub-ai/pipeshub-ai/pull/2641) — @R0gue-one), with follow-up bug fixes ([#2750](https://github.com/pipeshub-ai/pipeshub-ai/pull/2750) — @kaushal1999).

### Bulk user invites from CSV/Excel

Admins can upload a CSV or Excel file of email addresses; the server parses, validates, normalizes, and deduplicates them, processes invitations asynchronously, and notifies the admin with a result summary — replacing the previously disabled "Import CSV" placeholder ([#2715](https://github.com/pipeshub-ai/pipeshub-ai/pull/2715) — @anupPradhan0).

### Richer retrieval context from the knowledge graph

Retrieved records are now enriched with related records from graph edges (parent, child, attachment), and dependent records such as Jira attachments or Linear docs carry their parent ticket/project metadata into the LLM context ([#2596](https://github.com/pipeshub-ai/pipeshub-ai/pull/2596) — @darshangodase), with a follow-up fix for passing location into `to_llm_context` and graph enrichment ([#2840](https://github.com/pipeshub-ai/pipeshub-ai/pull/2840)).

## Breaking changes & upgrade notes

- Knowledge-base record groups are migrated to connectors; the migration runs as part of this release ([#2650](https://github.com/pipeshub-ai/pipeshub-ai/pull/2650) — @tushar1245).
- Parsing and extraction now run as separate services controlled by a flag — review your deployment config before enabling ([#2541](https://github.com/pipeshub-ai/pipeshub-ai/pull/2541), [#2734](https://github.com/pipeshub-ai/pipeshub-ai/pull/2734)).
- The Atlassian site URL field was removed from connector configuration ([#2693](https://github.com/pipeshub-ai/pipeshub-ai/pull/2693)).
- The PipesHub Docker image RAM limit was increased — check host sizing ([#2853](https://github.com/pipeshub-ai/pipeshub-ai/pull/2853)).
