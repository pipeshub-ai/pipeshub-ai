## Rules

- **X-CARRIED-PINS** (impossible): Only a code_task job inherits a parent's first-use pins (R31-HOT2): a top-level run pins at its own first use, and a deep sub-agent's parent (a saved agent) names its tools (X-WHOLE-SEEDED)
- **X-CARRIED-SEEDED** (impossible): A saved agent's job is granted named tools, which Node pins at admission; there is no first-use pin to carry (X-WHOLE-SEEDED)
- **X-CLASSIC** (impossible): Today's loop pins nothing: no at-first-use listing, no mounted skills, no harness budget, no governed memory; it cannot hold a call for a person (a write that needs approval is refused approval_unavailable, oracle of e2e_covering_array.py) and has no ask-back
- **X-NAMED-OWNER** (impossible): The default chat holds each of the person's servers whole (the assistant definition, backend/python/app/api/routes/agent.py, atFirstUse); a server named tool by tool is a saved agent's
- **X-WHOLE-SEEDED** (impossible): A saved agent's server grant names its tools (run-spec.ts grantedTools: only a definition with atFirstUse holds a server whole, and only the assistant's has it); its named servers are still listed at first use, which mcp.named on the same paths runs
- **X-CLASSIC-OWNER** (out_of_scope): The owner's default chat runs Agent mode on the harness (ASSIST1); a classic default chat is the seeded shape's legacy switch (CTL-7), which classic/seeded covers
- **X-SCHEDULED** (impossible): A scheduled run is unattended: it is granted no memory write scope (P7.3), its turn carries no chat files, and nobody is in the chat to stop it or delete it (an operator's cancel is surface ops, OPS-01)
- **X-RESUME** (out_of_scope): A resume continues the pinned run: these act at admission or apart from the run, and their cell on the path the run started on holds them; what a resume must keep (the MCP pins, the decision, the answer, its files, its budget, its cancel) stays in
- **X-SUBAGENT** (out_of_scope): They act on the parent's conversation: the parent's cell (agent.deep) holds them; a child is stopped and erased with its parent
- **X-COMMAND** (impossible): A /run command is one run_code call with no model (SLASH3, runKind command): it offers no tool, asks nothing and answers nothing
- **X-ERASURE-CLASS** (out_of_scope): Erasure acts on what a person or org stored, not on a run: the data a path leaves is the same kind per executor (conversations, journal, workspaces, sandboxes, memories), so classic, assistant.agent, agent.quick, job.opencode and scheduled.cron stand for the rest (equivalence classes, ADR-TEST-01 D4)
- **X-SERVICE-PERSON** (impossible): A service account holds no person's own servers or sign-ins, has nobody to ask back and keeps no personal memory
- **X-SURFACE-MCP-CARDS** (impossible): An external MCP client sends no files, and a call held for approval waits in the inbox (Needs you), where approval.allow on the start path holds it
- **X-SANDBOX-CODE-LOOP** (impossible): The agent-code profile is a durable loop run's (sandboxProfileFor: executor loop only); an engine job runs in its own engine sandbox and today's loop pins nothing at admission
- **X-REPO-LOOP** (impossible): repository_fetch is served only by an engine job's Tool Gateway (ph git clone, WP-63 part A): a loop run reads code through a connected repository or a web fetch. The default chat and a saved agent reach it through the job they hand the work to, the job.* cells on the owner, owner_pinned and seeded shapes
- **X-CHAT-MODE-CODE** (impossible): The assistant's search modes offer no run_code (their tool set is the mode's: knowledge or web search, artifacts, skills, the person's question); code runs in Agent mode, whose assistant.agent cells hold it
- **X-CHAT-MODE-TOOLS** (impossible): The assistant's search modes are knowledge-only or web-only by design (R50JFIX-5): Node grants internal_search the organization's knowledge and no tool, web_search the web search tool and no knowledge, never an MCP server or a toolset (run-spec.ts assistantGrant; a run with no agent definition pins no skill), and the worker's mode policy loads only those (app/agents/chat_modes/policy.py, app/harness/assembly/chat.py build_chat_environment). So no server is held for a first use, a capability search, a hub runner or an OAuth sign-in, nothing is pinned to preload, and nothing the mode calls writes outside or sends, which is what a card, an org rule, the flow guard and a decline ask about. Agent mode's assistant.agent cells hold every one of them; skills load on demand and memory are run on the mode
- **X-CONTRACT-LOOP** (impossible): ADR-RUN-03: the grounding check (the not-found note, the question before a job, the evidence-capped confidence) runs where a turn hands work to a coding engine or may; a loop run with no engine authority answers under the contract's prompt alone, as classic chat does, so there is no not-found note or capped confidence to observe. The default chat's cells (assistant.agent, smoke and AC-E) and every job.* cell hold the check
- **X-CONTRACT-SLACK-SEEDED** (impossible): The seeded agent's Slack bot runs the loop agent, which has no engine authority (X-CONTRACT-LOOP)
- **X-CONTRACT-SLACK-OWNER** (impossible): The default assistant's Slack bot answers a lookup on its loop (R50JFIX-11): on the lane its run handed nothing to a job (no child; the thread got the loop's own reply), and ADR-RUN-03's grounding check runs only before a hand-off (app/harness/assembly/grounding_gate.py, loop.py _ground), so a loop answer has no not-found note or capped confidence to observe (X-CONTRACT-LOOP). Whether that Slack run should be offered code_task is R50JFIX-FU-1
- **X-SUBAGENT-ASK** (impossible): A sub-agent cannot ask the person (TAG_UI_ONLY, harness_core/tools/tags.py; ADR-RUN-03 may_ask): its need goes up as an [ESCALATION] that the deep coordinator asks (ADR-RUN-04 D1 amended by R36-COVER), the agent.deep cell
- **X-STEER-NOBODY** (impossible): Nobody is in a scheduled run's chat to write to it, a /run runs no model to read a message, and today's loop takes no message while it runs (steeringRefusal not_durable): the web app waits for its answer
- **X-PERSON-SCOPED** (impossible): No second person can act in the conversation: a saved agent's conversation is shared read-only (es_validators agentConversationShareParamsSchema) and a deep sub-agent is its child; a scheduled run and /run have one person; today's loop holds no call for anyone (X-CLASSIC)
- **X-DECLINE-CARRIED** (impossible): Nothing is declined to carry: today's loop holds no call for a person (X-CLASSIC) and /run makes no tool call (X-COMMAND)
- **X-SITES-LOOP** (impossible): Allowed websites reach only an engine job's sandbox (RunSites is built for engine runs; a loop run's code sandbox has no website egress), so the flow hold has nothing to hold there; the assistant's search modes run no code at all (X-CHAT-MODE-CODE)
- **X-AFTER-HOLD-LOOP** (impossible): Only an engine job's Tool Gateway holds a call and answers it deferred past the hold (ADR-RUN-06): a loop run suspends on its ask, and the default chat and a saved agent reach the rule through the job they hand the work to, the job.* cells
- **X-FIND-READ** (impossible): A saved agent, its deep sub-agent, a schedule, the MCP surface and /run name each server's tools from the attachment (X-WHOLE-SEEDED); only the default chat holds a server whole, the case where nothing names its tools before its first use
- **X-FIND-READ-SAVED** (impossible): A saved agent names each server's tools from its attachment (X-WHOLE-SEEDED), so nothing is found by capability on its runs: its coder agent's jobs, its resumed and recovered runs (they start on agent.quick) and its Slack bot; the person's own undescribed server is not the agent's to use
- **X-PLAN-NOT-OFFERED** (impossible): The plan tool is offered to root loop turns only (ADR-OWD-07 D-PLAN-1): today's loop journals no task.*, the assistant's search modes answer from one source and are never offered it, a deep child is planned by its parent's create_plan, and a /run runs no model

## Tiers

- **gate**: 253 journeys (every feasible feature x path the runner implements once, on the path's primary shape, plus every must-run cell)
- **full**: 717 journeys (every feasible cell the runner implements, every shape of every path (exhaustive: paths x shapes is small))
  - full tier only, **FO-ACP-GATEWAY** (130 journeys): These reach an ACP job through the Tool Gateway or the job's sandbox controller, the same code for every engine; the gate runs each on the native engines, and on every ACP engine the turns its ACP mapper words differently (files and commands, cards, the budget cut, cancel, a clone); the capability search and a message joining a running job (R47-JOURNEY) are the gateway's and the parent's, the same for every engine
  - full tier only, **FO-CLAUDE-GATEWAY** (29 journeys): The same gateway and sandbox paths the gate runs on the owner's Codex job and on opencode; Claude Code's own mapper runs in its use, deny, allow, budget, cancel and repository journeys
  - full tier only, **FO-WEBHOOK** (19 journeys): A signed webhook changes only how the firing starts, which the gate's webhook use journey proves; the scheduled run's features run on scheduled.cron in the gate
  - full tier only, **FO-RECOVERY** (15 journeys): Each kills the worker and the query service and runs alone (about 75 s); the gate's recovery allow journey proves the property that matters most, an approved write done exactly once by the new attempt; the run's own budget, code and memory turns on a recovered run run in the full tier too
  - full tier only, **FO-MEMORY** (8 journeys): A memory journey runs alone; the gate keeps it on the default chat and the owner's Codex job, where the owner keeps memories
  - full tier only, **FO-HUB** (23 journeys): A hub journey runs alone (it makes the servers and ends every owner's token); the credential and runner path is the query service's and the worker's Tool Gateway's, the same for every executor (MCP-E2E's finding), so the gate runs it on the default chat, a saved agent, deep mode, the opencode job and Slack
  - full tier only, **FO-CARRY** (19 journeys): Node declines the repeated call the same way for every engine's parent and every loop's next turn (ConversationGrantReach); the gate runs it on the owner's Codex job, the break MR-9 records, and on the default chat's next turn
